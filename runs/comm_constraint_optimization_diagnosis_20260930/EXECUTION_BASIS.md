## 一、项目背景与当前目标

系统包含三个部分：

1. PILOC 搜索模型：已训练，冻结；
2. CTDE 任务分配模型：已训练，冻结；
3. 通信控制器：决定候选消息 SEND/HOLD，是当前研究对象。

主线是：

> 在尽量保持按时完成任务数的前提下，降低已计量通信成本。

不是搜索重训、任务分配重训，也不是单纯追求消息更少。

### 指标与目标定义

- `Y`：每 episode 按时完成的任务数，不是完成率百分点。
- `C`：已计量载荷尝试字节；丢包仍计费。
- 接收端交付次数不等于发送尝试成本。
- 视距感知、gossip 等旁路不在当前受控通道成本中，不能称为全系统通信成本下降。
- SEND 被预算拒付不计成本，但不能当成主动节省。

当前训练目标：

```text
c = C / B0
g = E[Y_reference] - E[Y_policy] - δ

L_max = -E[c] - λ*g
A_actor = λ*A_task - A_positive_cost

λ_next = max(0, λ + ηλ*g_hat)
```

登记参数：

```text
B0 = 10000 B
δ = 0
λ_initial = 1
ηλ = 0.05
```

λ 单位是“归一化成本/任务数”。δ=0 是实验训练目标，不是部署零退化保证。

## 八、对偶尺度只做描述性检查，不调参

在同一场景集合、同一计量口径内，可比较已有策略的：

```text
Jλ = −平均归一化成本 + λ*平均按时任务数
```

reference 和 δ 对候选策略比较是共同常数。

如果两个已有策略 A、B 的任务均值不同，可计算其经验交叉点：

```text
λ_cross = (c_A − c_B) / (Y_A − Y_B)
```

要求：

- 使用同一组场景；
- 明确训练或开发来源；
- greedy、sampled 分表；
- 任务差为零时不计算有限交叉点；
- 不用开发结果反向选 λ；
- 不把经验交叉点称为最优 λ、充分条件或部署参数。

这项分析最多说明：在某个已观察策略集合和经验数据上，当前标量目标如何排序。它不证明神经网络能到达那些策略，也不证明改变 λ 就能解决问题。
