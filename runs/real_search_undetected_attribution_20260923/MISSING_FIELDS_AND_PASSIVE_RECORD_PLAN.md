# 缺失字段与最小被动记录方案（B1）＋ 两个正确性候选的复现计划

**本轮不实现、不补跑。** 这份文档只回答两件事：现有记录到底缺哪几个字段（有负证据），
以及把"未发现"从"不可判"变成"可判"最少需要加什么。

## 一、缺哪些字段（负证据来自 360 个生命周期文件的逐记录扫描）

| # | 字段 | 为什么必须有 | 现状 |
|---|---|---|---|
| F1 | 逐时刻搜索机器人格 `(step, agent_id, row, col)` | 判定"是否曾进入合法探测范围"的唯一正证据 | **0/360 文件有** |
| F2 | 逐时刻未发现目标格 `(step, target_id, row, col)` | 目标每步自己走一格；没有它，"轨迹覆盖了这个格子"这句话没有对象 | **0/360 文件有** |
| F3 | episode 截止时两个后端的位置（搜索侧 + 目标侧） | 区分"来不及"与"永远到不了" | 0/360 |
| F4 | 逐步或分段的覆盖事实（首次覆盖某格的步、团队并集覆盖曲线） | "搜索覆盖到该区域的时刻"这一项要求 | 0/360；`search_coverage` 是发现比例，不是空间覆盖 |
| F5 | 目标被删除那一步的 `(target_id, cell, observer)` 三元组 | 让"适配器发出的事件集合 == 环境删除的集合"成为可核对的不变量 | 事件里有 id/cell，但没有 observer 的格 |

PILOC 环境在内存里**已经有** F1 的一部分（`agent_positions_history`，`timemap.py:284`、
`410-414`、`913-925`，只保留最近 10 步且从不落盘），F2 的目标数组 `goals_pos` 每步都现成。
所以缺的是落盘，不是计算。

## 二、B1：最小被动记录方案（沿用 B0 的全部纪律）

只加一个被动探针，写侧文件，**不新增生命周期 `event_type`、不进 actor 观测、不改奖励、
不改通信配置、不消耗任何随机数**。

### 记什么（按"事件式"写，不逐步刷盘）

```text
kind=search_step    step, agent_id, row, col         # 仅在机器人位置变化时写（PILOC 允许原地停）
kind=target_step    step, target_id, row, col        # 仅在目标位置变化时写
kind=observed_pair  step, target_id, agent_id        # 判据在第 577-593 行的谓词为真的那一步
kind=cut_positions  仅一次：episode 结束时搜索机器人与剩余目标的格
```

`observed_pair` 是**复用环境已经算过的结果**（`_observed_goal_indices` 的返回集合），
探针只读不重算，因此不会引入第二套判据口径——这条很重要：如果分析脚本自己另写一份
"距离 ≤5 且视线通"的判断，就会有两套定义（第十七轮的分析正是这样做的，
并用 72 457 个格对 0 分歧的交叉核对把它钉住）。

体积估计（60 集 × 1000 步、6 目标、2 机器人）：变化式写入约每集 20–60 KB，
一批 60 集约 2–4 MB；逐步写入上限约每集 0.4 MB。两者都远低于 B0 的量级，
并且照例不入 Git，只在启动账本与结果件里登记路径与哈希。

### 验收（与 B0 同规格，硬门禁）

1. **成对回放**：同一 seed、同一臂，开/关 B1 各跑一次，比较
   全部生命周期记录（剥离身份字段与传输层自描述后逐字段）、检测序列、发射序列、
   `airtime_bytes`、`(on_time, expired, discovered)` —— 必须全同；重复格必须自洽。
2. **不消耗随机数**：这一步比 B0 更要紧，因为 `goals_pos` 的移动由环境的 `_py_rng` 驱动
   （`timemap.py:820`），探针读一个随机数就会把整条轨迹换掉。验收方式：探针开/关时
   逐步比较 `env._py_rng` 与 `env._np_rng` 的状态位（比特发生器 state），并比较
   **每一步后的 `goals_pos` 与 `agents_pos` 数组**（不只 episode 结局）。
   任何一步之后位置不同 ⇒ 判据失败，停止一切数据运行。
3. 探针文件里的 `(step, agent, goal)` 三元组必须与同一次运行生命周期里的发现事件
   **逐条闭合**（出现 `observed_pair` 而未产生事件的，就是 §三 的靶）。

## 三、两个候选的最小复现（本轮不跑）

靶：B1 批的 seed `1100051`（放置 `[18,44]`）与 `1100053`（放置 `[22,58]`）——
某个搜索机器人的**起点格本身就在该目标的合法可见集合内**（起点→可见集测地距 0、
切比雪夫 ≤5、视线通），但该目标整场 1000 步没有发出任何发现事件。

**为什么现在不能判**：`Environment.step` 在 682 行先移动机器人、在 778 行才做观测判定，
所以"起点看得见"不等于"第 1 步看得见"；此后 999 步的位置没有任何记录。

**最小复现步骤（有 B1 之后，单条命令、单集）**：

```text
1. 用 seed 1100051 跑一次真实 PILOC（其余配置与 D1 的 A1 臂逐字段相同），开 B1 探针；
2. 从 B1 重建两条位置路径，按 577-593 行的判据逐步复算 (agent, goal) 可观测谓词；
3. 断言：复算得到的"首次为真"集合与生命周期里的发现事件集合逐条相等；
4. 若存在"谓词为真但没有事件"的步 ⇒ 复现成功，这是正确性问题；
   若不存在 ⇒ 这两个候选被判为"轨迹未覆盖"，本桶关闭，§二 的 B1 也就能给整批结论。
```

**若复现成功的修复计划（顺序固定，不并发改）**：

1. 先加**失败测试**：在同一 seed 上断言"适配器发出的发现事件集合 == 环境该步删除的目标集合"
   （现在的实现分别在 `integrated_sar/adapters/piloc.py:129-147` 与
   `piloc/src/Map/timemap.py:778-782` 各算一遍同一判据——两份实现、两个调用点，
   这就是这类缺陷的成因结构）。
2. 修复取其一，且只取其一：
   * (a) 让环境把本步的 `observed_indices` 与移动前的 `goals_pos` 快照一起返回，适配器只做翻译，
     不再自己重算（单一判据持有者）；
   * (b) 若必须保留适配器侧判定，则加一条运行时不变量：两侧集合不等即抛错，禁止静默继续。
3. 修复后必须重跑：成对回放证明行为未变（或如实报告行为变了），
   并重新登记受影响的臂；**不得**用修复后的实现追改第十六轮任何结论。
4. 已知关联：`AGENTS.md` 的"PILOC 发现后立即删除 `goals_pos`，适配器只是兼容方案"
   就是这条结构的登记处；修完要更新那一行。
