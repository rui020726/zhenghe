# 修正环境在线系统验证（CORRECTED_ENV_SYSTEM_VERDICT）

条件：回放块通过正确性门槛且无未解决退化之后才启动（门槛见 `CORRECTED_ENV_HELDOUT_VERDICT.md` 第三节）。
60 个额外未使用 seed（500400..500459，与回放块 400 个不重叠，同一条排除规则），
真实 PILOC 在线搜索（不使用任何 detection stream），两臂同一修正环境、同一现有模型，
配置真值表与构造断言完全相同。产物：`system_block/<arm>/system_*_s<seed>.json`，
汇总 `SYSTEM_SUMMARY.json`。

## 二、解耦不变量：检查而不是假设

每个 seed 两臂的**有序检测序列**（目标 id、检测时刻、发现它的搜索机器人）必须逐字段相同
（按 SHA256 比对）。**60/60 全部相同** → `decoupling_invariant_holds = true`。

这意味着两臂确实面对同一个搜索世界，配对比较成立；也意味着这条链路里
**没有任何从分配回到搜索的通路**——搜索侧看到的、报出的东西与协调器开关无关。

## 三、这块能说什么、不能说什么

能说：
* 系统集成正确——把录制流换成真实在线搜索输入，两臂仍然构建自同一冻结代码、同一环境变体，
  构造断言全部通过，没有任何一集崩在边界之外；
* 解耦不变量在真实搜索输入下**经验成立**（检测序列逐字节一致）；
* 在当前场景难度（num_goals=6、grid 60、检测半径 5、搜索机器人 2）下，
  瓶颈是**搜索覆盖率**（360 个目标里 5 个从未被发现）而不是分配——
  凡被发现的目标两臂都 100% 按时完成。

不能说：
* 不能说它证明了任何**新的双向反馈能力**——恰恰相反，它验证的是"没有反馈通路"；
* 不能把它当成对候选收益的第二次独立检验：60 集里两臂**逐集相同**，这块对这个难度
  **没有可分辨的信号**（ceiling），既不支持也不否定回放块的结论；
* 不能报推断性区间：60 seed 的样本量按预注册只做描述。

## 四、遗留

* 若要让在线块真正区分两臂，需要提高难度（更多目标或更紧的 deadline），
  使"发现了但没按时"成为可能——本轮没有调难度，因为那会引入一次新的、未预注册的实验。
* 在线块没有插桩释放/覆盖计数（那些在回放块按 episode 全量测过）。若需要在线侧的
  同一套正确性账本，需要把 `corrected_block` 的探针搬进 `system_v2`——一次单独的改动。
