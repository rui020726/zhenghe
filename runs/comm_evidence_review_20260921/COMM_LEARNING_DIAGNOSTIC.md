## 四、观测合法性：发送端能推断什么

| 决策需要的问题 | 观测里合法可用的量 | 边界 |
|---|---|---|
| 这条消息有多紧急（离 deadline 多远） | remaining_time_over_horizon、urgency_now（belief 里的截止时间，不是注册表真值） | 截止时间随消息到达，晚到的视图带来晚到的紧急度；紧急度不是真值剩余时间 |
| 还剩多少预算 | budget_remaining_fraction、capacity_remaining_fraction | 是发送端自己账本的余额，与规则臂同一条执行器；不含未来到达包的字节预估 |
| 反馈不确定性（接收端到底收到没有） | /2 的 confirmed_fraction、max_ack_age_scaled、max_view_gap_scaled、unacked_broadcasts_scaled；无 ACK 时显式 unknown(-1.0) | 只由自身发送历史与已到达 ACK 推出；在途包、接收 belief、真实丢包结果均不可见 |
| 这条视图是不是新闻 | changed_view、first_emission、stage_changed、requirements_changed、members_changed、progress_delta_abs、revision_delta | 全部来自发送端可见的视图差分 |
| 队列与规模压力 | queue_backlog_targets、subscribers、step_over_horizon、age_steps、since_last_emission_time、sent_count、pending_event | 无目标 id 类特征进网络（避免记忆具体场景） |

**只有评估器/模拟器知道的量（不得进在线 actor）**

- 注册表真值状态与真 revision（TaskRegistry）
- 未来的检测事件与未来任务结局
- 接收端 belief 的实际内容与信息年龄
- 本包/本 ACK 的真实丢包结果与在途队列
- 评估器按 target_id 聚合的按时/超时结局

## 六、四种解释的证据表（允许并存）

### undertraining — 在 400k 环境步的资源上限内仍未收敛到位

- **支持**：曲线里 100k→400k 仍在改善：'last_minus_first' 见 runs[*]['curve_delta']；每 run 的 optimizer.step 只有 3.1k–6.1k 次，决策样本 18.8 万–37.7 万条；48 条训练流被重放 8–9 次，不是 400 个不同场景
- **反对**：六个运行全部显著优于各自未训练初值（CI 下界 > 0），说明梯度信号确实在起作用；seed 间完成率极差在扩训后缩小（第二轮 1.833→0.042 的同型现象）
- **仍缺**：value loss 未持久化：只有 explained variance、KL、clip 与熵可查；未保存每里程碑的贪心动作熵（只有 rollout 期间的 ent/ent_free）；没有更长期限的运行可比较（资源上限是预注册的，本轮不追加）
- **当前状态**：不能排除，也不能确证

### insufficient_observation — 发送时机真正需要的状态量不在观测里

- **支持**：紧急度与剩余预算都在观测里；缺的是'别的消息/别台机器人的状态'类全局量——但那是设计约束（不变量 9），不是遗漏；learned2 与 send_once 逐包序列在 15/24 流上完全相同 ⇒ 观测足以复现该规则的行为
- **反对**：同观测下 learned1 达到全表最高均值 5.9167 个/ep（虽未过门槛）；policy_owned_timing 下自由决策占比 100%（无代发掩码），不是'动作被掩码定死'的老问题
- **仍缺**：没有做过消融：把某个特征置零/替换后重训的对照不存在（需新训练授权）；发送端能否合法推断'这次不发的代价'只有间接证据（门禁 3 的单步反事实）
- **当前状态**：无直接证据；需要干预实验而非再训练

### temporal_credit_assignment — 一次 HOLD 的后果在若干步之后才出现，单步奖励把它冲淡了

- **支持**：本轮实测口径：奖励是每个按时目标记 1 分、记在发生的那一步 ⇒ 与发送决策之间隔着行程与工时；单步反事实里 96.5% 的SEND/HOLD 差被后续策略补偿掉（打平），正是'后果被后续动作吸收'的画像；下一轮协议（多步干预）存在的唯一理由就是把 horizon 拉长到能看见这种补偿
- **反对**：打平也可能意味着该步本身确实无后果，而不是后果被延迟——单步数据无法区分二者；ACK 反事实中字节轴同样大量打平（363/425），若只是延迟成本，字节应先于完成数分化
- **仍缺**：已有 trace 不能回答'一次 HOLD 后多久被补发'：反事实 transcript 每 seed 只保留最后一个点的运行，且未标强制步；需要跨步干预与补发间隔统计（见协议 §5）
- **当前状态**：最可疑、但当前证据最薄；是下一轮的唯一优先问题

### strong_rule_at_reachable_effect — 在这个任务分布与这套信道下，强规则已经接近可达效果，学习没有额外空间可占

- **支持**：本轮 200 新流：noack_send_once 以 14 605 B/ep 拿 4.48/5.515/5.81 个/ep，是被反复复现的强锚点；第二轮起所有'省通信'收益都可由共享静默上界或规则改写解释（hold_to_bound、send_once）；本轮规则前沿里没有任何臂在有统计支持的意义上支配锁定规则
- **反对**：规则的合法性变化本身就带来过收益（协议收益≠学习收益，但说明'规则已够'依赖协议定义）；ACK 规则在隔离有损上拿到 +0.835 个/ep ⇒ 规则集合的上界还会随反馈协议移动
- **仍缺**：'可达效果'需要一个不依赖学习的上界参照（如全知调度 oracle），当前没有做过；正常路径上旁路（视距+gossip）使任何发送时机的边际价值被稀释，未单独量化
- **当前状态**：与前三项不互斥；不能作为关闭学习路线的理由

## 七、读这张表的规则

- 环境步、候选决策数、真正自由决策数、optimizer.step 是四个不同的量，不得互为代理
- explained variance / KL / clip fraction / 熵只作健康度诊断，任何单一阈值都不构成收敛证明
- 完成数相同不等于策略相同：逐消息序列一致率必须单独给
- '不能排除某解释'不等于'该解释是原因'；本表不允许被引用为训练追加依据
