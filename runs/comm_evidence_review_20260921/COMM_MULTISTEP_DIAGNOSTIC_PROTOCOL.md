## 1. 待检验的假设（可证伪，不是已发现的根因）

**一次 HOLD 是否很快被后续重试补偿，从而掩盖了发送时机跨多个时间步的任务影响？**

- 已有的间接证据（`COMM_LEARNING_DIAGNOSTIC.md` §五、第六轮门禁 3）：425 个**单步**受控点里
  410 个（96.5 %）完成数打平，字节轴 363/425 打平。
- 该观测**不能**区分两种解释：(i) 该步本身确实无后果；(ii) 后果存在，但在 H>1 步的窗口里才被
  后续动作实现或被后续重试抵消。单步干预在设计上无法区分二者。
- 因此本实验的唯一目的是**把 horizon 拉长到能区分 (i) 与 (ii)**，不是为了证明模型可用。

若结论是"没有跨步影响"，那是对当前方法的负结果加一条边界；若是"有跨步影响但本地观测辨不出"，
下一步是信息契约讨论而不是训练。**本文件不预先承诺 RNN、奖励塑形、更大模型或更长训练有效，
也不宣布必须换场景。**

## 3. 时点选择：固定 seed + 事前 eligibility，不看结局

1. **候选事实来源**：第六轮已记录的 eligibility 探针
   （`COMM_ACK_VALUE_COUNTERFACTUAL_25pct.json` 的 `probe_points`，逐流列出
   `step / target / changed_view / confirmed_fraction / rule_sent / unacked / age_steps`）。
   这些都是**事前状态量**，不含任务结局，因此选择过程不会挑好案例。
2. **合法且非硬掩码**：该时点在该流的决策记录里必须是一个真实候选（该候选进入过策略且
   `actual_assignment` 索引未被硬掩码排除，按不变量 6 核对）；强制 SEND 还必须**付得起**当步字节，
   付不起则该点作废并记 `refused_insufficient_credit`，**非法动作永不执行**。
3. **有意义的状态**：`0 < confirmed_fraction < 1` 且 `changed_view` 为真（与第六轮 eligibility 同定义），
   即"部分订阅者已确认、部分未确认"——这才是重试规则会分歧的状态。
4. **抽 16 条**：`numpy.random.default_rng(20260921)` 在按 seed 升序排列的 48 条流上不放回抽 16 条，
   每条流在其候选点里按同样方式抽 1 个；选择清单与两分支的事前状态摘要必须在**第一条分支 episode
   之前**提交为 `COMM_MULTISTEP_POINTS.json`。
5. **无可用点的流如实报告**：`no_informative_point` 计入缺额，**不从别的 seed 补抽**，
   也不放宽 eligibility 定义来凑数。实际点数 ≤ 16 即按实际点数算规模。

## 4. 干预的三种估计对象（estimand），与"发一次 ≠ 每步都发"

对每个选定时点 `t*`、目标消息视图 `v = (target, revision, content_fingerprint)`：

| 分支 | 定义 | 说明 |
|---|---|---|
| `S(H)` | 在 `t*` **强制发送 `v` 一次**，并在 `[t*, t*+H)` 内禁止该视图再次发送 | H=1 即"单步强发"，与第六轮同口径 |
| `H(H)` | 在 `[t*, t*+H)` 内**禁止发送 `v`**，无论策略请求什么 | 窗口内该视图一条都不上空气 |
| `free` | 不强制，策略自己决定（仅作一致性校验，不计入 96 分支） | 见 §7 |

**必须区分的三件事**：

- "发一次"（`S(H)`：一次发射 + 窗口静默）与"整个窗口每步发送"（本设计**不含**该分支，
  因为它是另一种协议而非更长 horizon）；
- H ∈ {1, 5, 20} **不是同一个 estimand** 的三次重复：`S(20)` vs `H(20)` 回答的是"20 步内发/不发的
  总效应"，`S(1)` vs `H(1)` 回答"这一步"。三者分开报告，不得合并成一个"多步效应"；
- 主比较对是同一 H 下的 `S(H) − H(H)`；跨 H 的差只用于看窗口长度的单调性，不用于造显著性。

**窗口语义的四个规定**（写死，不留解释空间）：

1. 窗口作用于**视图 `v`**，不作用于 target 也不作用于整个队列：别的 target、别的订阅者消息、
   gossip 与视距感知照常演化。
2. 若窗口内该 target 产生**新 revision**（内容真变了）：新视图是另一条消息，**不受旧窗口约束**，
   由固定后续策略决定；旧视图的剩余窗口终止，记 `window_truncated_by_revision`，
   并报告截断发生在第几步。这是 `S`/`H` 两分支共同的规则，不偏向任何一支。
3. HOLD 是否阻止后续同一消息重试：**是**，窗口内该视图的重发请求被压制并计数
   （`blocked_requests_in_window`）；窗口结束后重试计数与未消耗额度**原样保留**（不预先扣除尝试次数），
   两分支各自的 `attempts_remaining_at_window_end` 必须报告，因为它决定了补偿是否可能。
4. 窗口结束后（`t* + H` 起）两分支都交回**同一条固定后续策略**继续到 episode 结束；
   策略身份、参数、额度、ACK 参数在两个分支逐字段相同并写入 `config_hash`。

固定后续策略：`retry_until_acked`，`max_attempts=2`（在 200 新流上被独立确认的那条），
`policy_owned_timing`、29 300 B、隔离信息路径、上下行成功率 0.7（丢包率 0.3）。
该选择在跑之前冻结，之后不得按结果更换。

## 5. 分支的可比性与随机数（不得暗换信道机制）

1. **分叉点状态一致**：两分支从 `t*` 前一步的同一模拟器快照恢复；快照摘要（含
   `step`、注册表 revision、各机器人 belief 指纹、队列与账本余额、ACK 已确认三元组）在两分支
   恢复后必须逐字段相同，并把该摘要写入 `COMM_MULTISTEP_RESULTS.json`。
   快照只用于**离线干预**，不是可部署策略；它也不是最优 oracle（它不知道未来检测与真值结局）。
2. **前向丢包（sequential RNG）**：每 episode 一个 `default_rng(scenario_seed)` 流、每次发射按
   subscriber 顺序一抽。两分支的发射序列一旦不同，**消耗位置就不同，后续逐包结果不再是同一串事件** ⇒
   跨分支的前向信道比较是**同分布**，不是同一实现。必须记录：
   - 分叉时该流已消耗的抽样个数 `forward_draws_consumed_at_fork`（两分支同值，作为快照一致性的一部分）；
   - 分叉后各分支新增消耗数 `forward_draws_after`；
   - 两者之差即"发射序列差异造成的抽样位移"，报告而不修正。
3. **反向 ACK（counter-based RNG）**：key = `(episode seed, "uplink_ack", subscriber, target, ordinal)`
   + 交付 tick。两分支在同一 key 上抽到同一个数（共同随机数）；某 key 只存在于一支时记
   `key_unpaired` 并单独计数。**不改用第二套更友好的反向参数，不提高丢包、不收紧 deadline。**
4. **不给 actor 真值特权**：强制动作由干预层施加，观测构造完全沿用 `/2` schema；
   registry truth、接收 belief、在途包、未来结局不得进入任何特征。干预层"知道"要强制哪一步，
   这是实验设计，不是策略能力。

## 6. 观察量（预注册，全部两分支成对报告）

| 量 | 定义 | 允许的读法 |
|---|---|---|
| Δ按时完成 | 逐 target 结局配对差（个），及新增失败/救回的点名清单 | 任务效应 |
| Δtotal 字节 | 上行尝试 + ACK 尝试（分列），B/episode 与 B/新增按时任务 | 成本效应，正号一律"更高" |
| 下一次补发间隔 | 从 `t*` 起该视图（或其新 revision）下一次发射的步数；无则记 `never` | **本实验的核心问题** |
| belief 首次分歧 | 各订阅者 belief 内容指纹首次不同的步 | 状态分歧 ≠ 任务效应提升 |
| 预算后果 | 额度使用率、拒付次数、`refused_insufficient_credit` | 取舍是否由额度产生 |
| 窗口机制计数 | `blocked_requests_in_window`、`window_truncated_by_revision`、`attempts_remaining_at_window_end` | 补偿是否被窗口规则本身制造 |
| 随机数位移 | §5 的两项消耗数与 `key_unpaired` | 说明两分支不是同一串事件 |

明确禁止的推论：**状态发生分歧不等于提高任务效果**；某个干预点更好**不证明**模型能用局部观测
识别它（干预层知道时点与视图，actor 不知道）。后者只能在观测消融或策略复现中讨论。

## 7. 规模上限与一致性检查

- 闭环分支：**16 点 × 3 个 H × 2 分支 = 96 条 episode 上限**（实际点数少则按比例减少）。
- 另加**最多 16 次**前缀/复现检查：每点一条 `free` 分支，用于验证"未强制"路径与
  第六轮该点的记录逐字节一致（若不一致，本实验的复现接口不成立，见 §8）。
- 每条 episode 1 000 联合步 ⇒ 约 96 000–112 000 环境步、最多 112 条 episode。
  按第七轮实测吞吐 2.53 s/ep 估 ≈ 5 分钟级串行、单点产物 ≈ 2.8 MB ⇒ 磁盘上限约 0.3 GB。
  执行时记录**真实**仿真步数与耗时，不用估算值充数。
- 分片只在执行轮使用（沿用 `shard_of` 单一实现）；产物命名必须**逐点唯一**
  （`cf_s<seed>_p<point>_H<H>_<branch>.jsonl`）——第六轮的反事实转录因按 seed 命名而被同 seed 的
  后续点覆盖，导致补发间隔无法归因，本实验必须避免同一缺陷。

## 8. 停止与阻塞条件

- 若恢复接口无法做到 §5.1 的事前状态逐字段相同、或 §7 的 `free` 一致性检查失败，
  **提交阻塞说明并停止**：不重构整套训练器、不改信道机制来凑可复现性。
- 若技术失败，只按预登记原因（进程被杀、磁盘满、checkpoint 加载失败）用**同一时点**重跑并登记次数。
- 不设"必须发现若干正例才继续"的伪理论门槛；点数少或结局稀疏时，结论允许是**不确定**。
  零显著性不构成对模型路线的否定，正例不构成对部署的肯定。

## 10. 设计结尾：三条有限分支（事前写定）

1. **存在跨步任务影响，且发送端合法观测可辨**（补发间隔在两分支显著错位、且首次分歧可由 `/2`
   特征解释）⇒ 建议下一轮**只改一个训练因素**（信用分配或表征二选一），保持强规则与全部
   环境/协议参数不变。
2. **反事实可改善，但本地观测辨不出**（有跨步效应、但干预信息不在合法观测里）⇒
   **先讨论信息契约**（发送端应被告知什么），不进入训练。
3. **无可辨信号**（补发间隔与结局在两分支都对齐）⇒ **保留当前方法的负结果**；
   是否继续需要一条有现实依据的新研究假设（例如非平稳信道或真实任务压力）交使用者决定，
   并先做无模型 learnability calibration。
