## 16. 不限预算 / 成功率约束下省字节（revision_02）

本节记录 `recovery_12/revision_02` 的设计、开跑前拦下的四个缺陷，以及第一个检查点
（episode 100）的逐 cell 结果。**结论是否定的：15 个 cell 没有一个达到
"成功率 ≥ 95 % immediate 且字节更少"。**

### 16.1 目标改成了什么

| | revision_01 | revision_02 |
|---|---|---|
| 预算 | 58,600 B，硬约束 | **1,000,000,000 B**，只是上限 |
| 成本刻度 | `bytes / 10,000` | **`bytes /(N·G)`**，再按参考 cell 归一到 `bytes/10,000` |
| 成本系数 | 固定 0.1 | **λ，对偶变量** |
| 规模 | 单一天地 | **(G, R, N) 每回合重抽** |
| 特征维度 | #14/G、#17/6 | **#2/G、#14/G、#17/6** |
| 强规则 | immediate、always_hold | 再加 **dedup_immediate** |

λ 规则照任务原文实现，且只在 PPO update 边界移动：

```
lambda <- clip(lambda + 2 * (q - 0.95 * q_ref), 0.25, 8)     初值 2.0
```

`q` = 本批 `sum(on_time)/sum(generated_goals)`；`q_ref` = **同 cell** 的
`normal_immediate` 按时率。一个 batch 通常横跨多个 cell，因此 `q_ref` 是按
`generated_goals` 加权的同批 cell 均值，缺参考的 cell 会被点名而不是被替换。

### 16.1b 第五节：一个更严重的接缝缺陷（milestone_100 之后才发现）

**milestone_100 的评估不是对目标的合法读数。**原因是接缝：特征变换挂在
`controller.inner.trunk` 上，但 `world` 在**回合结束时**就把它还原了，而 PPO update 在那之后才跑。
于是 update 前向的是**原始** `tape["features"]`，而策略采样时用的是**改写后**的行。

实测（真实顺序：采样 → 还原 → update）：`max |logp_sample − logp_update| = 0.109`（update 0，
参数尚未动，正确值必须为 0）。这解释了两件此前我当成"策略行为"来记录的事：

- `approx_kl` 11–17（clip 只有 0.2）——不是策略跳得远，而是重要性比算在了不同的输入上；
- 那次评估的成功率与字节数都建立在这个错误的基础上。

修法：把改写抽成纯函数 `apply_rewrite()`，由 trainer 用**每个样本自己的 cell** 调用。
cell 必须随样本走，因为一个 minibatch 混着多个 cell，而每个 cell 除以自己的 `G`。

修后实测：`max |dlogp| = 0.000e+00`；trainer 里 `approx_kl` 从 0.186 降到 **0.00041**。
闸门增至 **56 项**，新增三条：还原后 update 的回归、混合 cell 的 minibatch、以及
`cell_transform` 缺失时必须报错而不是静默用原行。

**因此 16.4 的 0/15 与 16.5 的机制描述都作废**，保留在此仅作为失败记录。
`train_v2` 被 `train_v3` 取代，后者跑在修好的接缝上。

### 16.2 开跑前拦下的四个缺陷（每条都记在 README 的失败账本里）

**① 成本量级错了，这一条最关键。**按任务原文 `c = bytes/(N·G)`，一次发送约
2.4 kB，在 `N=6, G=12` 下就是 **33 个刻度单位**，而一个被转化的任务只值
`A_task = 1 − V(s) ≈ 0.41`。即使 λ 取到下限 0.25，一次发送仍是任务价值的 **8.5 倍**，
所以在整个注册区间 `[0.25, 8]` 内"永不发送"都是最优。

第一次训练（`train_v1`）把这个预言一字不差地跑了出来：

| | |
|---|---|
| 366 次 update 中零发送 | **342 次** |
| λ 停在下限 0.25 | 359 次 |
| 整段训练发出的总字节 | 0（从 ep 5059 起） |

修法不是改注册，而是**纯重标定**：乘上参考 cell 的 `N·G / B0`，使
`(N, G) = (6, 24)` 时精确复现每轮归档用的 `bytes/10000`，其它 cell 仍按
`N·G` 比例定价。这样 λ 既跨 cell 同义，也与此前所有轮次同义。修完 `probe40`
40/40 回合都有发送、λ 在 1.36–3.54 之间正常浮动。

**② `num_goals` 还在和冻结字面量 24 比较**，于是 G=12 / G=48 的 10 个 cell 全部被拒。
`grid_v1` 因此 **360 个基线世界失败 240 个**。改成与本 cell 自己的期望比，
并额外断言该值在注册网格内。

**③ 规则臂的产物命名空间无法区分同一场景的两个 cell** —— 第二个 cell 必然
`FileExistsError`。cell 标签折进 arm 槽位解决。

**④ `dedup_immediate` 的"实质变化"太宽**。把 `progress_delta` 计入后有 372 次发送
/ 24 个目标（progress 几乎每 tick 在动）；去掉后仍有 138 次（`members_changed`
每次改派都会跳）。最终默认只认**阶段推进**，实测 53 次发送 / 24 个不同目标。

### 16.3 闸门

`tests/test_revision_02_gates.py`：**53 项全过**，任务点名的六条各一个类 ——
预算绑定/恢复（含 world 抛异常时的恢复、被移动的权威会被拒）、成本与 transcript 对账
（含参考 cell 复现 `bytes/10000`、其它 cell 按 `N·G` 比例、零刻度被拒、量级回归）、
任务信用守恒、λ 方向与双侧裁剪、`N ≤ R` 与 15 个 cell 的网格、以及
采样/critic/PPO **三条路径看到同一行**且第 0 次更新 ratio < 1e-6。

基线：`grid_v2` 覆盖 **15 cell × 8 场景 × 3 臂 = 360/360 世界，0 失败**，
`q_ref` 从 0.3464（G48_R6_N3）到 0.9948（G24_R12_N12）。

### 16.5 这批数字说明了什么

**成功率确实上去了。**三个 `R=12` 且 `G ≤ 24` 的 cell 达到或超过 immediate
（G24_R12_N3：1.000 vs 0.891；G24_R12_N12：1.000 vs 0.995；G12_R12_N3：0.972 vs 0.958）。
G48_R12_N12 也从 0.823 提到 0.931。

**但代价是 6–16 倍的字节。**每个 cell 都比 immediate 多花一个数量级，最多的
G48_R12_N12 多花 **16 倍**。所以"省钱"这一半完全没有实现，而且方向是反的。

**机制上可以指认。**训练日志里 λ 从 2.0 一路升到 5.0（clamp 上限是 8），说明对偶
确实在按规则"发现 q 高于目标 → 提高字节价格"；但同一时段每次 update 的发送数中位数
从 85 涨到 **773**。也就是说：**成本项在涨，发送量涨得更快。** 这与成本项的量级
仍不足以压住"多发一次就多一分按时率"的边际收益一致，但本检查点**没有**
做 λ 的量级消融，所以这只是机制描述，不是因果结论。

**还有一个必须写下来的观察：KL 异常大**（11–17，而 clip 是 0.2）。这说明重要性比
严重越界，策略在 update 之间跳得很远。按任务熔断表，"NaN"没有出现（损失与梯度都有限），
所以熔断没有触发；但这么大的 KL 意味着**这批方向的可靠性本身要打折扣**，
不能把 milestone_100 的表现当成收敛行为。

### 16.6 能不能说

**能说**：

- 在 `recovery_12/revision_02` 的这组开关下，N=15 个 cell 的单检查点评估中
  **没有一个**达到"成功率 ≥ 95 % immediate 且字节更少"。
- 预算是 1e9，且**所有世界 credit mask 为 0**、预算权威退出后恢复（逐世界记录在行里）。
- λ 按注册公式移动：2.0 → 5.0，方向与 `q − 0.95·q_ref` 的符号一致，未触上界。
- 成本刻度已修到与归档轮次同量级；修前 `train_v1` 的 342/366 零发送是**量级缺陷**的
  后果，不是策略性质。
- 成本刻度修后 `probe40` 40/40 回合有发送、无熔断，说明"永不发送"的死锁已解除。

**不能说**：

- **不能声称跨 cell 最优或已到帕累托前沿**：本节没有任何一行与另一行相比。
- **不能把 R 的差异说成 N 的效果**：`R=12` 的 cell 成功率普遍高于 `R=6`，这是执行
  能力（劳动力）的差别，与订阅者数无关；表中 `G24_R6_*` 与 `G24_R12_*` 的差距全部
  属于 R。
- **不能说"dual 无效"**：只看到一个检查点、一轮 seed、每 cell 3 个场景；且 KL 11–17
  说明这条轨迹本身没有收敛，任何关于 λ 机制的结论都需要更低 KL 的重跑。
- **不能说这就是收敛值**：milestone_100 只是第一个存档点，训练仍在继续。
