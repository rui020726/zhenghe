## 16. 不限预算 / 成功率约束下省字节（revision_02）

本节记录 `recovery_12/revision_02` 的设计、开跑前拦下的四个缺陷，以及第一个检查点
（episode 100）的逐 cell 结果。**结论是否定的：15 个 cell 没有一个达到
"成功率 ≥ 95 % immediate 且字节更少"。**

### 16.1 目标改成了什么

| | revision_01 | revision_02 |
|---|---|---|
| 预算 | 58,600 B，硬约束 | **1,000,000,000 B**，只是上限 |
| 成本刻度 | `bytes / 10,000` | **`bytes /(N·G)`**，再按参考 cell 归一到 `bytes/10,000` |
| 成本系数 | 固定 0.1 | **λ，对偶变量** |
| 规模 | 单一天地 | **(G, R, N) 每回合重抽** |
| 特征维度 | #14/G、#17/6 | **#2/G、#14/G、#17/6** |
| 强规则 | immediate、always_hold | 再加 **dedup_immediate** |

λ 规则照任务原文实现，且只在 PPO update 边界移动：

```
lambda <- clip(lambda + 2 * (q - 0.95 * q_ref), 0.25, 8)     初值 2.0
```

`q` = 本批 `sum(on_time)/sum(generated_goals)`；`q_ref` = **同 cell** 的
`normal_immediate` 按时率。一个 batch 通常横跨多个 cell，因此 `q_ref` 是按
`generated_goals` 加权的同批 cell 均值，缺参考的 cell 会被点名而不是被替换。

### 16.1b 第五节：一个更严重的接缝缺陷（milestone_100 之后才发现）

**milestone_100 的评估不是对目标的合法读数。**原因是接缝：特征变换挂在
`controller.inner.trunk` 上，但 `world` 在**回合结束时**就把它还原了，而 PPO update 在那之后才跑。
于是 update 前向的是**原始** `tape["features"]`，而策略采样时用的是**改写后**的行。

实测（真实顺序：采样 → 还原 → update）：`max |logp_sample − logp_update| = 0.109`（update 0，
参数尚未动，正确值必须为 0）。这解释了两件此前我当成"策略行为"来记录的事：

- `approx_kl` 11–17（clip 只有 0.2）——不是策略跳得远，而是重要性比算在了不同的输入上；
- 那次评估的成功率与字节数都建立在这个错误的基础上。

修法：把改写抽成纯函数 `apply_rewrite()`，由 trainer 用**每个样本自己的 cell** 调用。
cell 必须随样本走，因为一个 minibatch 混着多个 cell，而每个 cell 除以自己的 `G`。

修后实测：`max |dlogp| = 0.000e+00`；trainer 里 `approx_kl` 从 0.186 降到 **0.00041**。
闸门增至 **56 项**，新增三条：还原后 update 的回归、混合 cell 的 minibatch、以及
`cell_transform` 缺失时必须报错而不是静默用原行。

**因此 16.4 的 0/15 与 16.5 的机制描述都作废**，保留在此仅作为失败记录。
`train_v2` 被 `train_v3` 取代，后者跑在修好的接缝上。

### 16.1c 第五节：一个统计口径错误，把"与 immediate 打平"读成了"崩到 0.3"

第一次聚合 milestone_100 时，`evaluate.py` 把学习臂**3 个场景**的 on_time 与基线
**8 个场景**的总和相比，于是每个 cell 的比值恰好落在 3/8 附近（0.298–0.460）。
我把这当成了"成功率崩了"，这是错的。

改成**同场景**求和后（`--recompute-from` 只重新聚合已归档的 45 个世界，不重跑任何世界），
真实形状完全不同：

| 事实 | 数值 |
|---|---|
| 15 个 cell 中字节与 immediate **逐位相同** | **15/15** |
| 每个 cell 发送数 = 不同目标数（零重复） | 15/15 |
| 成功率比值（同场景） | 0.85–1.01，多数 ≥ 0.95 |

也就是说，**milestone_100 的策略在行为上就是 immediate**：每个目标发一次、从不重发、
字节数一分不差。它不是"花 6–16 倍字节买成功率"，而是"完全没有省钱"。

`evaluate.py` 的默认行为已改为：给 `--recompute-from` 时，场景集合从归档文件继承，
不再默认用 8 个场景做分母。上面那次错误的输出仍留在
`execution/train_v3/eval_100_seamfix/EVAL.json`，重新聚合的结果在
`execution/train_v3/eval_100_seamfix_recomputed/EVAL.json`。

**修正后的判定仍然是 0/15**，但理由变了：不是成功率不足，而是**字节没有下降**
（因为与 immediate 完全相等）。

### 16.2 开跑前拦下的四个缺陷（每条都记在 README 的失败账本里）

**① 成本量级错了，这一条最关键。**按任务原文 `c = bytes/(N·G)`，一次发送约
2.4 kB，在 `N=6, G=12` 下就是 **33 个刻度单位**，而一个被转化的任务只值
`A_task = 1 − V(s) ≈ 0.41`。即使 λ 取到下限 0.25，一次发送仍是任务价值的 **8.5 倍**，
所以在整个注册区间 `[0.25, 8]` 内"永不发送"都是最优。

第一次训练（`train_v1`）把这个预言一字不差地跑了出来：

| | |
|---|---|
| 366 次 update 中零发送 | **342 次** |
| λ 停在下限 0.25 | 359 次 |
| 整段训练发出的总字节 | 0（从 ep 5059 起） |

修法不是改注册，而是**纯重标定**：乘上参考 cell 的 `N·G / B0`，使
`(N, G) = (6, 24)` 时精确复现每轮归档用的 `bytes/10000`，其它 cell 仍按
`N·G` 比例定价。这样 λ 既跨 cell 同义，也与此前所有轮次同义。修完 `probe40`
40/40 回合都有发送、λ 在 1.36–3.54 之间正常浮动。

**② `num_goals` 还在和冻结字面量 24 比较**，于是 G=12 / G=48 的 10 个 cell 全部被拒。
`grid_v1` 因此 **360 个基线世界失败 240 个**。改成与本 cell 自己的期望比，
并额外断言该值在注册网格内。

**③ 规则臂的产物命名空间无法区分同一场景的两个 cell** —— 第二个 cell 必然
`FileExistsError`。cell 标签折进 arm 槽位解决。

**④ `dedup_immediate` 的"实质变化"太宽**。把 `progress_delta` 计入后有 372 次发送
/ 24 个目标（progress 几乎每 tick 在动）；去掉后仍有 138 次（`members_changed`
每次改派都会跳）。最终默认只认**阶段推进**，实测 53 次发送 / 24 个不同目标。

### 16.4c 一个解析上界：这条判据本身给省钱留了多少空间

任务的判据是"同 cell 成功率 ≥ 95 % immediate **且** 字节更少"。把 P5 的恒等式
（**完成集合 = 被广播的不同目标集合**，16/16 世界零误差）代进去，就能在不训练的情况下
算出这条判据允许的最大节省：

> 要保持 immediate 的 `ok` 个成功，就必须至少广播 `ceil(0.95 · ok)` 个**不同的**目标；
> 每个不同目标约花同样的字节（immediate 零重复），所以
> **最大节省 = 1 − ceil(0.95·ok)/n**，其中 `n` 是 immediate 的广播数。

逐 cell 计算（用 16.4b 的同 3 场景基线）：

| cell | immediate 广播 n | 其中成功 ok | 95 % 门槛需要的广播 | 最大节省 |
|---|---|---|---|---|
| G12_R12_N12 | 35 | 35 | 34 | 2.9 % |
| G12_R12_N3 | 35 | 34 | 33 | 5.7 % |
| G12_R12_N6 | 35 | 35 | 34 | 2.9 % |
| G12_R6_N3 | 35 | 28 | 27 | 22.9 % |
| G12_R6_N6 | 35 | 29 | 28 | 20.0 % |
| G24_R12_N12 | 72 | 71 | 68 | 5.6 % |
| G24_R12_N3 | 72 | 57 | 55 | 23.6 % |
| G24_R12_N6 | 72 | 72 | 69 | 4.2 % |
| G24_R6_N3 | 72 | 49 | 47 | 34.7 % |
| G24_R6_N6 | 72 | 37 | 36 | 50.0 % |
| G48_R12_N12 | 142 | 109 | 104 | 26.8 % |
| G48_R12_N3 | 142 | 111 | 106 | 25.4 % |
| G48_R12_N6 | 142 | 120 | 114 | 19.7 % |
| G48_R6_N3 | 142 | 49 | 47 | 66.9 % |
| G48_R6_N6 | 142 | 56 | 54 | 62.0 % |

三点必须一起读：

1. **在 immediate 已经饱和的 cell 里，判据只留 2.9 %–5.7 % 的空间。** `R=12` 且
   `G ≤ 24` 的五个 cell 就是这一类：immediate 成功 35/35、72/72、71/72，几乎没有可丢的。
   在这些 cell 里"成功 ≥ 95 % 且字节更少"最多只能省 3–6 %，不是数量级。
2. **大节省只出现在低成功率 cell**（`G48_R6_*` 达 62 %–67 %），而那里的低成功率来自
   **劳动力不足（R=6）**，不是通信。要拿到这部分节省，发送方必须知道"哪些目标最终会成功"——
   这取决于分派与机器人能力，**不在 19 维里，也不在发送方的可见范围内**（Invariant-9）。
3. 因此这条判据在**当前环境**下不是一个"省一个数量级"的问题，而是一个
   "在最容易的几个点省 3–6 %"或"猜中哪些会失败"的问题。后者若用上 R/分派信息，就是
   用发送方不该有的信息换分数。

**这解释了为什么 16.4b 的 15/15 字节相等不是"策略偷懒"**：一个只会"每目标发一次"的策略
在饱和 cell 里已经贴着上界；它错在不会在低成功率 cell 里做减法，而做那个减法需要的是
执行侧信息。

这是**策略饱和**，不是"训练没生效"。最可能的解释是：greedy argmax 下"发送/保持"的选择被
压在一个极端，所以 logit 的小幅漂移不改变 argmax（这也是 16.4b 里 λ 在无差异点附近来回、

所以以上是机制假设而非结论。

**判定仍是 0/15，理由仍是"字节未下降"**，且现在多了一条更强的证据：
多训 100 回合、权重确实变化，**行为与字节数完全不变** ⇒ 这条训练路径在当前奖励与特征下
不会自发走向"少发"。

### 16.4e 与 dedup_immediate 的对照（任务要求但不算改善）

任务把 `dedup_immediate` 定为"学习臂必须对比的低成本强规则"。milestone_200 的逐 cell 配对：

| 结论 | 数值 |
|---|---|
| 学习臂字节 / dedup 字节 | **0.43–0.49，15/15 cell 都便宜一半以上** |
| 逐场景配对差（on_time）均值 | +4 到一个 cell、+2 一个、0 三个、−1 至 −5 六个 |
| 配对差 95 % CI 是否跨零 | 15 个里 **14 个跨零**；唯一不跨零的是 G48_R6_N6 的 [−10.84, −0.495]（**输**） |
| 胜负 | win 6 / tie 3 / lose 6 |

也就是说：**学习臂比 dedup 便宜约一半，成功率大体打平，但在 6 个 cell 上更低，且没有
一个 cell 的改善在统计上站得住。**

这不构成任务口径下的改善，原因有两条，必须同时写清：

1. **判据的参照物是 immediate，不是 dedup。**学习臂字节与 immediate 逐位相同（16.4d），
   所以"字节更少"这一半不成立；
2. **拿 dedup 当参照也不成立**：14/15 的 CI 跨零，唯一不跨零的那一个是学习臂输。

**能说的**：学习臂确实落在 immediate 与 dedup 之间——比 immediate 少重发（零重复）、
比 dedup 少发（dedup 会按阶段推进再发）。它**没有**用这个中间位置换来任何可检出的成功率收益。

### 16.4f λ 走了 31 倍，行为没动一步

按 λ 分档统计训练日志里的**每目标发送数**（`sends / G`，消除 G 的直接尺度效应）：

| λ 区间 | 回合数 | 每目标发送数中位 | 均值 | 平均 q |
|---|---|---|---|---|
| [0, 1) | 9 | 1.000 | 0.891 | 0.620 |
| [1, 3) | 21 | 1.000 | 1.221 | 0.804 |
| [3, 5) | 23 | 1.000 | 1.018 | 0.827 |
| [5, 8) | 15 | 1.000 | 1.008 | 0.897 |

λ 覆盖 **0.25 → 7.88（31 倍）**，每目标发送数的中位数**四档全部是 1.000**，
均值在 0.89–1.22 之间无趋势；而 q 随 λ 上升（0.62 → 0.90）——
这个方向与"提价减少发送"相反，符合"更多目标被覆盖故而更多成功"，而不是"被价格压住"。

**结论（有实测支撑）**：在这条轨迹上，λ 的 31 倍变化**没有可检出的发送量效应**。
这与 16.4d 的"权重动、行为不动"互为印证：greedy 决策落在"每个目标发一次"这个离散点上，
λ 只改成本项，改不动 argmax。

**不能说**："λ 无效"。只能说**在 λ ≤ 7.88 这段区间与这批 cell 上测不出效应**。

> **上面这条在 λ 触到上界 8.0 之后被推翻了一半**，见 16.4g：效应是**阈值型**，不是线性。
> 本节保留原读数，是因为它在它所覆盖的区间里仍然成立；把它当成"全区间无效"是错的。

### 16.4g λ 撞上上界后，发送量断崖式下降——效应是阈值型

`train_v3` 的 update 序列（每目标发送数 = `sends / G`）：

| 回合 | λ | 每目标发送数 | q |
|---|---|---|---|
| 5283 | **8.000**（上界） | 1.000 | 0.958 |
| 5287 | 8.000 | 1.000 | 0.958 |
| 5291 | 8.000 | 1.000 | 0.833 |
| 5295 | 8.000 | 0.958 | 0.958 |
| 5299 | 7.659 | 0.979 | **0.125** |
| 5303 | 7.223 | **0.500** | 0.500 |
| 5307 | 6.826 | 0.250 | 0.250 |
| 5311 | 6.166 | **0.083** | 0.083 |
| 5319 | 4.488 | 0.250 | 0.250 |
| 5331 | 2.136 | 0.188 | 0.188 |
| 5339 | 0.542 | 0.354 | 0.333 |

读法：

1. **λ 到 8.0 之前，每目标发送数一直是 1.000**（76 个 update 里没有例外）；
2. **λ 到 8.0 之后 40 个回合内，发送量跌到 0.08–0.5**——这是整轮训练里唯一的发送量变化；
3. **代价立刻出现在 q 上**（0.958 → 0.125），于是 λ 按注册公式回落（8.0 → 0.54），
   发送量随之回升（0.083 → 0.354）。

所以 λ **确实**在推策略，只是存在一个**阈值**：在 8 以下它推不动 argmax（16.4f），
到上界后它推得动，一推就过冲，然后被 q 的反馈拉回。这是一次**以 100 回合为周期的振荡**，
不是"λ 无效"，也不是"策略学会省字节"。

**milestone_300（ep 5299，λ≈8.0）的评估正好落在过冲上**：15 个 cell 的发送数被压到
10 / 16 / 44（G=12 / 24 / 48），q 掉到 0.21–0.31，字节只有 immediate 的 0.26–0.33 倍。
判定 **0/15**，理由是"成功率 0.30–0.46 倍 immediate，低于 0.95"——**这是过冲，不是改善**。

**这条对设计的直接含义**：注册的 λ 上界 8.0 恰好是"能推动"与"推不动"的分界线，
而可用的中间档位（例如 3–5）推不动。要让 λ 平滑工作，需要么扩大上界并让它稳在中段，
要么改变奖励尺度使 λ 的中间值就具备推动力。**本轮不改注册值**，只记录现象。

### 16.4h 过冲之后：臂终于变成选择性的，但覆盖不足压住了收益

过冲（16.4g）之后 λ 被 q 拉回 0.25–2.1，发送量停在每目标 0.08–0.5。这个区间给出了本轮
**唯一一次"臂在做选择"** 的读数：

| | 过冲前（74 个 update） | 过冲后（14 个 update） |
|---|---|---|
| 每次发送的转化率 `on_time / sends` | 均值 0.813 | **均值 0.928** |
| 每目标发送数 | 1.000（几乎无例外） | 0.08–0.50 |

也就是说：**少发的时候，发出去的那些更容易转化成按时完成**——它确实挑了一部分目标
（转化率 0.81 → 0.93）。但这**换不成总分**：`G48_R6_*` 这类 cell 里目标总数 144，
只发 17–18 个就注定丢掉大部分任务，而丢的那些与"挑得准"无关——16.5 里 P5 的恒等式
（完成集合 = 被广播集合）在这里同样成立：**没发的目标不会完成**。

因此这一段的净效果是"省字节但丢任务"，落在判据的错误一侧：

- 字节：immediate 的 0.26–0.33 倍（省了 70 %）
- 成功：immediate 的 0.30–0.46 倍（**远低于 0.95 门槛**）
- 判定 0/15，理由是成功率不足

**这仍然不是"改善"**，但它证明了一件对后续有用的事：这条奖励 + 这套特征**能**推出
选择性发送，只是现有 λ 区间里"有选择"与"够覆盖"不能同时成立——因为 **λ 的可用档位是
二值的**（8 以下不动，8 以上过冲），中间没有稳定点。

### 16.4k 判据何时可以收工：用"通过的条件"而不是"跑到多少回合"来定

**问题**：这一轮没有回合上限，唯一的停法是熔断。但熔断表里没有"已经足够好"这一项，所以需要一条**基于证据的停止规则**，否则只能一直烧算力。

**先把已有证据摆成相位表。** 每个 checkpoint（间隔 25 个 update）写档时 λ 的取值与训练里那一段的每目标发送数：

| checkpoint | 写档前 λ | 该段 sends/目标 | 相位 | 评估结论 |
|---|---|---|---|---|
| 100 | 0.48 | 1.000 | 全发 | 0/15（与 immediate 相同） |
| 200 | 3.91 | 1.083 | 全发 | 0/15 |
| 300 | 7.22 | 0.500 | **选择性** | 0/15（过冲，只留 38.8% on_time） |
| 400 | 2.32 | 1.000 | 全发 | 0/15 |
| 500 | 6.30 | 1.000 | 全发 | 0/15 |
| 600 | 0.82 | 1.000 | 全发 | 0/15 |
| 700 | 5.27 | 1.000 | 全发 | 0/15 |
| 800 | 8.00 | 0.917 | **选择性** | **5/15**（2 条经复核成立） |
| 900 | 0.88 | 1.000 | 全发 | 0/15 |
| 1000 | 5.71 | 1.000 | 全发 | 0/15 |
| 1100 | 7.86 | 0.875 | **选择性** | 2/15（两条均靠抽签） |

**读法**：11 个检查点里只有 3 个落在"选择性发送"相位（300/800/1100），判据的通过也只出现在这一相位。这不是巧合：**能不能达标由相位决定，与总回合数无关**。280 个 update 里 59 个（21.1 %）处于选择性相位，其余 79 % 的训练时间策略与 immediate 完全相同。

**这条给了可执行的停止规则**（按优先级）：

1. **达标即停（首选）**：在某次"选择性相位"里评估，出现 ≥ 1 个 cell 满足"成功率 ≥ 95 % immediate 且字节更少" **且** 同目标集合复核通过（像 G12_R12_N3、G48_R12_N3 那样），就停了——判据已经达到，继续训练不改变结论。**已经出现过两次（milestone_800 的两个 cell，在未见场景上也复现：G12_R6_N3 0.981、G12_R12_N3 0.983、G24_R6_N3 0.959、G24_R12_N3 0.974、G48_R12_N3 0.970）**。若要求更强，则等"≥ 3 个 cell 经复核成立"。

2. **相位耗竭即停**：再跑 2–3 个选择性相位（每个约 55–60 回合，历史上 4 次、间隔 200–400 回合），如果每次复核成立的 cell 数不增加（此前是 2 个，1100 是 0 个），说明"达标点"就是这条奖励能到的地方，停。预计再观察 1 000–1 500 回合（约 6–9 小时）。

3. **熔断**：现成的六条，继续有效（至今 0 次）。

**不建议的停法**：按总回合数（如"跑到 3000 再看"）。理由是证据表明 79 % 的时间在做与 immediate 相同的事；把回合数当停止条件只会增加落在非选择性相位的概率，而不会提高达标概率。

**若要真正解决"不稳定"**（不是本轮授权内）：需要 λ 的可用中间档（扩大上界并让它稳在中段），或让奖励尺度在中间 λ 就有推动力；以及探测时刻即可分的信息（当前最优 AUC 0.63）。这两件不做，选择性相位会一直只占 ~20 %，通过与否取决于评估恰好落在哪一相。


### 16.5 早期读数（train_v2 / milestone_100，**接缝修复前**）——已被 16.5b 取代

> 保留原文是为了让"读错过什么"可查。这里的 6–16 倍字节与 KL 11–17 都是**接缝缺陷的产物**：
> 更新期与采样期的特征行不一致（16.1b），策略在 update 之间被推得很远。修复后 `train_v3` 的
> `approx_kl` 是 1e-4 量级，字节与命中数则回到与 immediate 相等（16.4i）。**不要引用本节数字作结论。**


**成功率确实上去了。**三个 `R=12` 且 `G ≤ 24` 的 cell 达到或超过 immediate
（G24_R12_N3：1.000 vs 0.891；G24_R12_N12：1.000 vs 0.995；G12_R12_N3：0.972 vs 0.958）。
G48_R12_N12 也从 0.823 提到 0.931。

**但代价是 6–16 倍的字节。**每个 cell 都比 immediate 多花一个数量级，最多的
G48_R12_N12 多花 **16 倍**。所以"省钱"这一半完全没有实现，而且方向是反的。

**机制上可以指认。**训练日志里 λ 从 2.0 一路升到 5.0（clamp 上限是 8），说明对偶
确实在按规则"发现 q 高于目标 → 提高字节价格"；但同一时段每次 update 的发送数中位数
从 85 涨到 **773**。也就是说：**成本项在涨，发送量涨得更快。** 这与成本项的量级
仍不足以压住"多发一次就多一分按时率"的边际收益一致，但本检查点**没有**
做 λ 的量级消融，所以这只是机制描述，不是因果结论。

**还有一个必须写下来的观察：KL 异常大**（11–17，而 clip 是 0.2）。这说明重要性比
严重越界，策略在 update 之间跳得很远。按任务熔断表，"NaN"没有出现（损失与梯度都有限），
所以熔断没有触发；但这么大的 KL 意味着**这批方向的可靠性本身要打折扣**，
不能把 milestone_100 的表现当成收敛行为。

### 16.5b 中期判定（train_v3，接缝已修，截至 milestone_600 / ep 5607）——后续见 16.4j

| 项 | 读数 |
|---|---|
| 训练 | `train_v3`，episode 5000 起，至本文写就时 165 个 update / ep 5659，6 枚 checkpoint，**0 次熔断** |
| 评估 | 每个 checkpoint 15 cell × 3 场景 = 45 世界，6 点共 270 世界，**0 技术失败** |
| 改善 cell | **0 / 15**，六个检查点全部如此（**700/800/900 之后这一条被改写：800 达到 5/15，见 16.4j 与本节的"后续"段**） |
| 判据未达的方式 | 100/200/400/500/600：字节**恰好等于** immediate（发送集合逐步相同）；300：字节减到 28 %，成功率掉到 0.30–0.46 倍 |
| λ 轨迹 | 2.0 起，全程 min 0.250 / max 8.000，触上界 5 个 update、触下限 11 个，结束 0.526；零发送 update 为 0 |
| 预算 | 1e9；45/45 世界 `masked_by_credit = 0`、`budget_restored = True` |
| P5 恒等式的独立复核 | 90 个世界（学习臂 + 基线）里"已完成但从未发送"的目标 **0** 个（共 1798 个完成目标） |

**结论：任务目标未达成。** 注册的判据（同 cell 成功率 ≥ 95 % immediate 且字节更少）在 15 个 cell 上
一个也没成立，且不是"差一点"：五个检查点上学习臂与 immediate 是**同一个发送函数**，
一个检查点上它是 immediate 的过小真子集。

**为什么不是"再训久一点就行"**：λ 的可用档位在这个奖励尺度上是二值的——[0.25, 8) 内推不动
argmax（142 个 update 每目标发送数中位数恒为 1.000），到 8.0 一次性过冲。要在判据上得分，
需要的是**可用的中间档位**（更大上界并把 λ 稳定在能推得动的中段，或改奖励尺度让中间 λ
就有推动力），以及**探测时刻就能分辨"会不会按时完成"的信息**（当前可见量的最优 AUC 0.63）。
两者都不在本轮授权的改动范围内（不改注册常量、不做 full_features）。

### 16.5c 后续（700/800/900，覆盖 16.5b 的"未达成"判定）

`train_v3` 继续跑并产出 milestone_700/800/900。**milestone_800 有 5 个 cell 满足注册判据**
（G12_R12_N3、G24_R6_N6、G24_R12_N3、G48_R6_N6、G48_R12_N3），字节分别省 2.8 % / 32.6 % / 4.2 % /
33.0 % / 3.8 %，成功率 0.971 / 1.000 / 1.140 / 1.089 / 0.964 倍 immediate。700 与 900 仍是 0/15。
详见 16.4j。

因此**16.5b 的"目标未达成"只对前六个检查点成立**，不是这一轮的最终结论。当前能说的准确定位是：

- 判据**可满足**：800 有 5 个 cell 通过（其中 2 个在标准 3 场景、5 个在 5 个未见场景上经同目标集合复核成立），
  1100 有 2 个整 cell 通过（复核均不成立）；
- 但**不稳定**：700 → 800 → 900 → 1000 → 1100 依次是 0/15、5/15、0/15、0/15、2/15。
  11 个检查点里只有 3 个落在选择性相位，其余 8 个的发送集合与 immediate 相同或近乎相同；
- 800 的 5 个通过里，**只有 2 个**在同目标集合的复核下仍然成立（G12_R12_N3 33/34、G48_R12_N3 107/111），
  另 3 个（G24_R6_N6 0.730、G24_R12_N3 0.947、G48_R6_N6 0.821）整 cell 数字过线但经不起投递抽签复核；
- 真正稳定的省钱幅度离解析上界还很远：G12_R12_N3 上界 5.7 % 实际 2.8 %；G48_R12_N3 上界 25.4 % 实际 3.8 %。

### 16.6 能不能说

**能说**：

- 在 `recovery_12/revision_02` 的这组开关下（预算 1e9、`c = bytes/(N·G)` 按参考 cell 重标定、
  λ ∈ [0.25, 8] 起于 2.0），**判据在 milestone_800 上被 5 个 cell 满足**（见 16.4j）：
  成功率 0.964–1.140 倍 immediate、字节省 2.8 %–33.0 %。9 个检查点、405 个评估世界、0 技术失败。
- 但满足**不稳定**：相邻的 milestone_700 与 milestone_900 都是 0/15，且 700/900 的发送决策
  与 immediate 完全相同。5 个通过里只有 2 个在同目标集合复核下仍然成立
  （G12_R12_N3 33/34、G48_R12_N3 107/111），这两个是**真的少发**且幅度远低于解析上界
  （2.8 % vs 5.7 %、3.8 % vs 25.4 %）。
- 预算 1e9 确实是非约束的：所有评估世界 `masked_by_credit = 0`、`budget_restored = True`。
- λ 严格按注册公式移动，方向与 `q − 0.95·q_ref` 的符号一致（2.0 → 峰值 8.0 → 结束 0.526）。
- 判据的后半条在 100/200/400/500/600 上之所以不成立，是因为**发送决策与 immediate 逐步相同**
  （45/45 世界，1245/1245 次发送），而不是因为字节"多了几个百分点"。
- 选择性发送出现过两次：milestone_300 的过冲（发送 0.281、成功率 0.388 倍，落在判据错误一侧）
  与 milestone_800 的 5 个 cell（发送 0.717、成功率 0.763 倍，其中 2 个 cell 过线）。
  同一阈值机制，两次落在权衡曲线的不同位置。
- P5 的恒等式在本轮 90 个世界里独立复核成立：**已完成但从未被广播的目标 0 个**（1798 个完成目标）。
- `dedup_immediate` 作为低成本强规则**不省字节**：15 个 cell 全部比 immediate 贵 2.06–2.35 倍
  （它按阶段推进重发），所以"省字节"的参照只能是 immediate，不能拿 dedup 当省钱标杆。
- 在 95 % 门槛下，字节的解析上界是**总发送数的 31.2 %**（按 billed targets 计；单 cell 0–66.9 %），
  这个上界需要探测时刻不可得的信息：以"最终完成"为标签，探测可见量的最优 AUC 是探测步 0.6318，
  `deadline_offset` 0.5175、`severity` 0.5540、`total_stages` 0.4404。

**不能说**：

- **不能声称跨 cell 最优或已到帕累托前沿**：每个 cell 只与自己同 cell 的 immediate 比。
- **不能把 R 的差异说成 N 的效果**：`R=12` 的 cell 成功率普遍高于 `R=6`，这是执行能力（劳动力）
  的差别；`G24_R6_*` 与 `G24_R12_*` 的差距全部属于 R。`N` 只改变每次发送的扇出字节。
- **不能说"λ 无效"**：它在 8.0 处**有效且剧烈**（16.4g），只是可用档位二值化，
  中间值推不动 argmax。这是"λ 区间与奖励尺度不匹配"，不是"对偶没接线"。
- **不能说策略"稳定地学会了省字节"**：700/900 与 immediate 逐位相同，800 才是选择性发送；
  λ 在对数尺度上仍有 32 倍摆动，没有任何检查点显示稳定策略。能说的是"这条奖励链路能走到
  满足判据的点，但停不住"。
- **不能说这就是训练到收敛的结果**：训练没有预设回合上限，写就此文时仍在继续；
  λ 仍在 0.25–8 之间振荡，没有任何检查点显示稳定点。
- **不能把逐场景配对差里的 ±1–15 读成 cell 优劣**：`send` 与 `deliver` 行在同一 tick 内会重排；
  当发送集合与 immediate 相同时（100/200/400/500/600/700），45/45 世界的投递总数完全相同
  （5143/5143），差异来自 0.7 投递概率下的随机数消耗顺序。发送集合不同时（300/800/900），
  整 cell 的 on_time 差里同时含"少发"与"抽签重掷"两部分，必须按 16.4j 的同目标集合复核拆开。
