# 协议级补充指标：时延、双层交付率、能耗代理与吞吐

本报告把韩成（§2.1.3 的端到端延迟、传输成功率、能量效率、网络生存期）与高延忠（§3.2.3 的网络吞吐量、平均端到端时延）两套指标，映射到本 revision 已归档的评估日志上。**没有重跑任何世界、没有重训任何权重、没有改动 98 个 pin 文件**：全部读数来自`lifecycle.jsonl.gz` 与 `relay_transcript.jsonl.gz` 两个文件。

## 1　指标定义（符号化）

| 指标 | 一句话物理定义 | 符号公式 | 分母 |
|---|---|---|---|
| 中继滞留时延 | 一个目标从被发现到它第一次被放上信道所等的步数 | `D_hold(i) = t_emit(i) - t_disc(i)` | 无（逐目标，聚合时取分布） |
| 下游响应时延 | 从消息上行到该目标完成所花的步数，即接收方排队与执行的时间 | `D_resp(i) = t_done(i) - t_emit(i)` | 同上 |
| 端到端总时延 | 发现到完成的全部时间，`D_e2e = D_hold + D_resp` | `D_e2e(i) = t_done(i) - t_disc(i)` | 同上 |
| 链路包交付率 | 实际被订阅者收到的包数占尝试投递包数的比例 | `PDR_link = sum_e delivered(e) / sum_e attempts(e)` | 全部发射的接收者·次 |
| 链路丢包率 | 其补，实测值应与配置的投递概率一致 | `PLR_link = 1 - PDR_link` | 同上 |
| 任务级有效交付率 | 每条上行消息换来多少个按时完成的目标 | `PDR_eff = N_on / sum_e 1` | 发射总次数 |
| 受扰节点人次 | 每世界累计有多少个（接收者, 包）实例被真正送达 | `C_node = sum_e delivered(e)` | 世界数（报告里除以世界数） |
| 归一化通信能耗 | 发送与接收两侧按相对权重折算的字节量除以按时任务数 | `E_task = (a_tx * sum_e payload(e) + a_rx * sum_e payload(e) * delivered(e)) / N_on` | 按时完成的目标数 |
| 原始吞吐率 | 每单位时间放上信道的计费字节，与是否完成任务无关 | `Gamma_raw = sum_e cost(e) / (T / W)` | 时间窗数 `T/W` |
| 有效吞吐率 | 只计入最终按时完成的目标所占用的计费字节 | `Gamma_good = sum_{e: target(e) in on-time} cost(e) / (T / W)` | 时间窗数 `T/W` |

符号说明：`i` 为目标；`e` 为一次发射；`t_disc` 为检测事件时间戳；`t_emit` 为该目标第一次
发射的步号；`t_done` 为完成事件时间戳；`attempts(e)` 为扇出订阅者数（每次发射的尝试包数）；
`delivered(e)` 为其中真正到达的包数；`payload(e)` 为单份载荷字节；`cost(e)` 为按接收者计费的
字节（载荷 × 扇出）；`N_on` 为按时完成的目标数；`T` 为世界步数、`W` 为速率窗口长度；`a_tx`、`a_rx` 为收发两侧的相对
能耗权重。**公式里不出现任何具体数值**；参数取值单列在下文“参数取值”一段。


**参数取值**：`a_tx = 1.0`、`a_rx = 0.5`（收发两侧的相对字节能耗权重）、`W = 100` 步（速率窗口）。这三个是**参数**，不是公式的一部分。

**三条与归档口径的对应关系**（避免与既有表冲突）：

1. `on-time` 与论文表里的“按时完成”完全同义（`t_done ≤ deadline`），由同一批事件算出；
2. `cost(e)` 就是既有表里的计费字节（载荷 × 扇出），因此 `Gamma_raw` 与“字节/回合”只差一个窗口归一化；
3. `PDR_eff` 是既有“广播转化率”的另一种写法，此处按任务数而非消息数取分母。

## 2　方法论：确定性世界配对检验 vs 蒙特卡洛重复采样

两篇参考论文都用“同一配置重复仿真 N 次取平均”来消除随机性（高延忠：100 次蒙特卡洛）。本 revision 的做法不同，理由是可检验的：

1. **单个世界是确定性的**：`(scene, cell, probability)` 唯一确定一个世界，同一设定重跑结果逐字节相同。正文实验里已经验证过：把投递率 0.7 的一格在新管道上重跑，按时数、发射数、字节数与归档完全一致。因此对**同一个世界**重复采样只会得到零方差，再跑 N 次不增加任何信息。
2. **随机性来自世界之间的差异**：场景、目标布局、rescuer 编队、订阅者扇出共同决定结果，所以本报告把“重复”放在**跨世界**这一层——每组 24–120 个世界，而不是同一世界 100 次。
3. **配对而非独立**：所有方法跑在同一批世界上（同 (cell, scene, seed)），因此延时差异用**世界级配对检验**（Wilcoxon 符号秩，双侧）而不是两样本检验；这比蒙特卡洛取平均更严格——它同时控制了世界难度与样本量。
4. **代价**：跨世界重采样无法给出“同一世界内的时序方差”（本报告也没有报这个量），因为该方差在确定性世界下恒为零；凡是引用“均值 ± 离散度”的地方，离散度都是跨世界分位数，已在表头写明。

## 7　能说 / 不能说

**能说**

1. 高负载 R=6、G ≥ 36 的下游响应时延最低的是 **Pure-Policy (v4f)、Ours-Frozen (v4t)**（23.0 步，并列）。
   相对 immediate（63.4 步）少 40.4 步，逐世界配对 Wilcoxon 检验见上表。
2. 链路交付率与配置投递概率一致（见 §5 的 `PDR_link` 列），说明信道接缝没有改变；方法之间的差异来自**发多少、发什么**，不是来自链路质量。
3. `Γ_good / Γ_raw` 给出“信道占用里有多少最终兑现为按时完成”，可直接对标吞吐量口径。

**不能说**

1. **不能把 `D_resp` 当作纯网络时延**：它包含接收端的分配与执行时间，不是 MAC 层的排队时延；与高延忠的“平均端到端时延”只同量纲，不同构成。
2. **不能把 `E_task` 当能耗**：它是按收发相对权重折算的字节代理，没有射频模型、没有睡眠/计算能耗，只用于方法之间的相对比较。
3. **不能把 `PDR_link` 与 `PDR_eff` 混用**：前者是包的到达率（应≈配置 p），后者是每条消息换来的按时任务数，两者分母不同。
4. **不能说“更少的时延”等于“排序更好”**：`D_hold` 只在 `slack_matched` 上不为零（它按步发放，会把部分发送推迟），`v4t`/`v4f`/`immediate` 都是发现当步就发。因此两条时延曲线的差反映的是**下游响应**，不是“谁更早抢到信道”。
5. **不能把世界数当样本量重复使用**：同一次运行的世界既用于主表也用于本报告，配对检验已控制这一点，但跨表的数字不是独立证据。
