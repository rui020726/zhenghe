# ROUND38-R 研究恢复报告：通信成本与任务收益机制

日期：2026-10-02  
分支：analysis/comm-research-recovery  
分析对象：ROUND37 固定评估块 1600000..1600063；576 格，九臂各 64 场景。

## 结论与状态

ROUND37 的负结果保留。研究目标仍未达到：三个 greedy 学习臂在 64/64 场景的按时目标集合都与 always_hold 完全相同；其中 seed11、seed33 每集花费约 28.1 kB，seed22 则完全静默。相较 immediate，三个 greedy 臂都少 11 个按时目标实例，没有新增目标。

当前可由数据支持的近端机制线索有两种，不能合并成同一种失败：

1. seed11 与 seed33 的 greedy 行为发送很多后续刷新，消耗约 73% 计费字节；预算很早进入候选屏蔽状态。11 个 immediate 独有目标在这两个模型的首报机会均因预算屏蔽而不可发。
2. seed22 greedy 没有预算屏蔽；13,201 个合法候选全选 HOLD。对上述 11 个目标，首报候选可付，但 p(SEND) 只有约 0.029–0.035，greedy 仍选 HOLD。

这说明高通信成本和低通信成本的两个 seed 都没有恢复 immediate 的任务集合，但其直接行为瓶颈不同。逐目标时间链是机制证据，不构成刷新导致任务损失的因果证明。接收方丢包身份、superseded 前先到达的更高 revision 来源及完整协调器 belief 状态没有记录；不同臂尝试次数也不同，不能声称逐消息共享同一随机信道实现。

原 ROUND38 打包、演示和便携复现安排按最新决定暂停。当前工作转入针对方法机制的离线分析；规则臂只作参照，不能替代学习目标。ROUND37 的冻结评估结果和判定不改写。

## 通信成本具体花在哪里

发送端成本只按一次广播的载荷尝试字节记账；接收端结果按收件方尝试分别记数。因此接收尝试/交付数不可与广播数相加解释成发送次数。协议记录把后续非首次发射归为 refresh；没有独立自动 retry 事件类型。

| Greedy seed | 首发 数 / 字节 / 接收尝试 | 后续刷新 数 / 字节 / 接收尝试 | 所有广播及成本 | 接收端结果 | 预算行为 |
|---|---:|---:|---:|---|---|
| 11 | 190 / 469,764 B / 1,140 | 515 / 1,328,100 B / 3,090 | 705 / 1,797,864 B | 2,937 delivered：2,888 accepted、6 duplicate、43 superseded；1,293 lost | 每个场景均花掉至少 90% 的 29,300 B；每场景剩余 2–2,258 B；12,350 个候选被 budget mask，其中首报 8,933、刷新 3,417；63/64 场景后来有首报候选因预算不可付 |
| 22 | 0 / 0 B / 0 | 0 / 0 B / 0 | 0 / 0 B | 0 delivered，0 lost | 0 mask、0 拒付；13,201/13,201 个合法选择均 HOLD，p(SEND) 范围 0.0280–0.4122 |
| 33 | 198 / 490,014 B / 1,188 | 503 / 1,308,228 B / 3,018 | 701 / 1,798,242 B | 2,921 delivered：2,828 accepted、16 duplicate、77 superseded；1,285 lost | 每个场景均花掉至少 90% 的预算；每场景剩余 8–2,258 B；12,155 个候选被 budget mask，其中首报 8,764、刷新 3,391；60/64 场景后来有首报候选因预算不可付 |

在 seed11 和 seed33，刷新分别占广播数的 73.0% / 71.8%，占计量字节的 73.9% / 72.7%。首次 budget mask 的每场景步数中位数分别为 5 和 6，范围均为第 3–67 步。未付费的候选由采集器事前 mask，并没有进入发送器形成拒付。本批没有实际拒付，所以“拒付后仍有合法候选”不适用；按 tape 中的候选顺序，以首次预算屏蔽候选为界，seed11 后面仍有 6 个合法候选机会，分布在 6 个场景（2 个首报、4 个刷新，6 个全 SEND）；seed33 后面仍有 9 个合法候选机会，分布在 4 个场景（2 个首报、7 个刷新，其中 4 个 SEND、5 个 HOLD）。这些是其他候选仍可付，不改变 11 个 immediate 独有目标的首报当时不可付这一事实。seed22 没有预算屏蔽。

在 seed11 和 seed33 的 11 个 immediate 独有目标上，两个模型的目标首报候选均在发现/首个候选时被预算 mask；每条对应的目标路径未发生实际发射。seed22 的同 11 个首报候选均有预算可付、没有目标发射，其 greedy 选择是 HOLD，p(SEND) 为 0.0289–0.0354。seed22 不是被执行器拦住，也不是预算耗尽。这是“预算被刷新用掉”与“策略本身不请求首报”两种不同的观测路径。

seed11/seed33 合计 1,018 次广播中有 515+503=1,018 次刷新，占全部广播约 72%；刷新使用 2,636,328 B，占这两个模型共 3,596,106 B 的约 73%。可直接确认有许多接收结果为 superseded，但比例远低于丢失数；superseded 只说明到达的 revision 被接收侧作为较旧版本处理，不说明先前更高版本来自哪个 agent，也不能证明被替代消息没有任何其他作用。接收丢包只有每次发射的聚合数量，没有接收者身份。

- 对 learned 缺失目标：没有该目标的实际通信发送，因此不存在其发送后的接收端处理链；仍保留检测、阶段、任务过程及终态事件。

## 与既有 ROUND26–28 的关系

- ROUND26 对 ROUND25 原始整数和区间作独立复核，未改变原判定。1400031 的两个失败目标中，learned 比 immediate 迟报的消息全部 superseded；同时分配/作业链存在长空窗。它把失败归为多环节线索，未证明提前通信的普遍因果收益。
- ROUND27 在事后选定的 1400031 上覆盖首报。target-0 的 accepted 提前消息没有移动分配链或结局；target-5 的单次提前干预在该随机实现中伴随场景 4→6 个按时任务、成本减少 2,814 B。后续 RNG 和另一目标路径也发生变化，因此不能把整个变化因果归给一条消息或外推。
- ROUND28 在 16 个本来全按时的训练场景做 96 个首报干预：96/96 消息被接受，60/96 改变分配/作业链，0/96 改变任务结局，平均成本增加约 2,612 B。它没有检验失败目标能否被救回。

这些轮次已经做过首报提前干预；本轮不换个名字再做相同覆盖。它们没有测试“保留同一个学习策略的首报动作，只禁止后续 refresh 广播，使节省的预算继续参与之后的正常首报 affordability mask”。这正是下一建议与旧研究的差别。

## 报告精度与完成标准待确认

ROUND37 T4 的精确含义是：greedy 在所有未被屏蔽的自由候选上按 argmax 选择，即 p(SEND) 不低于 p(HOLD)；它不是“每个候选的 p(SEND) 都至少为 0.5”。seed22 的 p(SEND) 最高只有 0.4122；seed33 也有低于 0.5 的合法候选。已有 T4 仍通过，不应把判据转述成概率阈值检查。

| 待项目决策的完成标准 | 本轮状态 |
|---|---|
| 任务表现相对哪个参照 | 未确认；本轮列出 immediate、late 和 always_hold，尚未选唯一主参照 |
| 允许任务损失边界 | 未确认；不能把训练中的 δ=0 当成已验证的部署保证 |
| 成本改善相对哪个参照、至少改善多少 | 未确认；低成本但任务更差不能单凭字节认定优越 |
| 跨训练 seed 的稳定性要求 | 未确认；三个 greedy seed 的行为和成本方向不一致 |
| 新方法确认所需的独立场景要求 | 未确认；1600000..1600063 从本轮起属于方法分析块，不能再叫未参与开发的确认集 |

本轮不设置数值门槛、不因负结果降低标准。规则参照用于定位学习目标的缺口，不取代学习方法达标。
