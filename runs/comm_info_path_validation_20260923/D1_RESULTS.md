## 二、三个配对比较（本轮唯一的因果陈述）

主统计量：同 seed 的按时完成目标数差，配对百分位 bootstrap，B=10 000，RNG 20260923。

| 代号 | 比较 | 差（个/ep） | 95 % CI | 逐 seed 胜/平/负 | 范围 | 字节差/ep | 丢包差/ep |
|---|---|---:|---|---|---|---:|---:|
| **C1** | A1 − A2（上行说话 vs 完全静默） | **+0.31667** | **[+0.18333, +0.45]** | 17 / 43 / 0 | 0..2 | +14 573.3 | 0 |
| **C2** | A1 − A3（投递 1.0 → 0.7） | **0.00000** | **[0.0, 0.0]** | 0 / 60 / 0 | 0..0 | 0.0 | −10.25 |
| **C3** | A3 − A4（自带感知开 vs 关） | **+1.28333** | **[+1.01667, +1.55]** | 45 / 15 / 0 | 0..4 | 0.0 | 0 |

三条读法，按证据强度排：

1. **C3 是本轮最硬的一条**：两臂**发射序列逐条相同、逐包送达结局逐条相同、计费字节相同**
   （身份门禁 I2/I3 在全部 60 个 seed 上通过，因此可以说"**同一批丢包**"），
   A3 每集丢 10.25 个包造成 0 个任务损失，A4 同样 10.25 个丢失造成 **1.28 个/ep**。
    ⇒ 部署路径上"任务不掉"不是通信策略的功劳，而是环境自带感知把同一批损失吸收掉了。
2. **C2 给出精确的零**：60/60 个 seed 逐集相同，CI 是 [0,0]。
   注意这**不等于**"丢包无害"——它等于"**在视距刷新与 gossip 开着的时候**丢 30 % 的包不改变任务结局"，
   与 C3 是同一条事实的两面。且两臂计费字节相同：按尝试计费，丢掉的钱照付。
3. **C1 不是零**：把上行完全关掉要付 0.31667 个/ep（CI 下界 > 0，17 个 seed 有损、43 平、0 更好），
   买它的价格是 14 573.3 B/ep ⇒ **约 46 021 B/个额外按时任务**。
   与机制记录自洽：A2 的"整集无人知晓"目标数比 A1 多 **0.4500 − 0.1333 = 0.31667 个/ep**，
   与按时完成差**逐位相等**——这条一致性不是设计出来的，是两条独立口径撞到了一起。

| `S_all` / `S_det` / `S_unres` | **None / None / None**（空分母） | 0.88312 / 0.88312 / **0.0** |

**M3 的校准必须先读，否则上表会被误用**：在两个臂上，**按时完成的目标有 100 % 带着 M3**
（`m3_calibration.share_of_on_time_goals_flagged = 1.0`）。原因在代码里：belief 只在写入步更新，
而真值每步推进，所以"轮询式 belief 至少落后一步"是常态而非异常。
⇒ 按修订件 §二 的字面定义，M3 几乎不携带判别信息；`S_all(A4)=0.883` 完全由 M3 撑起，
**不能**被读成"88 % 的失败是信息造成的"。
把它当作程度量看才有意义：A4 的 belief age 中位 **823 步**、内容不一致占检查次数的比例中位 **0.985**。

真正有判别力的是三条零与一条非零：**A4 没有任何一个失败目标是"没送到""没人知道""知道得太晚"**；
77 个失败里有 9 个连 M3 都不带（纯执行侧），68 个带且只带 M3。
⇒ 在隔离条件下，`immediate`（每目标只报一次、永不刷新）造成的不是"消息没到"，而是
**"到达过一次的那条信息后来一直没人更新"**——这与收束件 §二 关于 `send_once` 的
"只被告知一次然后没做完"是同一件事，只是这次有了逐 (目标, 机器人) 的记录支撑。

## 四、冻结判据的机械适用结果

修订件 §四 的主口径固定为 A3。A3 的 `D_fail = 0` ⇒ `S_all` 分母为空 ⇒
守卫 G（`S_unres` 不可判或 > 0.5）触发 ⇒

> **`declared = "undecidable"`**：本轮**既不**判 N6 满足，**也不**判 N6 不满足。

这不是"实验失败"，而是判据在空分母上的正确行为：**部署路径在冻结难度下没有任何按时失败可供归因**，
所以"信息侧占失败的份额"这个问题在 A3 上没有定义。
把它写成"信息侧不是瓶颈"会超出证据（那是用 0 个失败除出来的），
把它写成"实验没结论"也不对（C1/C2/C3 三个干预差都是有效估计，其中 C1 与 C3 的 CI 下界都 > 0）。

如果使用者想让 N6 有一个可判的分母，唯一诚实的做法是在**另一次授权**下改变场景难度
（更多目标或更紧 deadline）——那会是一次新的预登记实验，而不是对本轮的修补；
本轮明确**没有**这么做（收紧 deadline 或加目标数在修订件 §七里禁止）。

## 五、本轮不声称的事

* 机制旗标是共现描述，不是因果：**只有 C1/C2/C3 三个干预差可以作因果陈述**（§一 的表）。
* "同一批丢包"这句话只对 C3 成立（I3 逐包核过）；C2 是"同一批包、阈值不同"的嵌套关系；
  C1 不得使用（一臂从不上空气，没有共享包序列可言）。
* 不把"部署路径 C2 = 0"外推成"丢包无害"或"通信研究无用"；它就是 A3 与 A1 在这批 seed 上的差。
* 不训练、不改 reward/λ/生产默认策略；本轮改的生产代码只有 B0 的被动日志
  （`D1_VERIFICATION.json` 列出改动文件集合并核对未越界，两个 checkpoint 的 SHA256 与
  修改时间均未被触碰）。
* 不把 `1100000..1100059` 称为学习模型的独立测试集：本轮没有任何学习策略跑在这批数据上。
* `800000..800399` 封存档上 artefact 仍为 0；`900000..900199` 仍是规则工程块。
* 内部一致性：逐目标链自己算出的每集按时完成数与项目原生 `window_metrics` 的结果
