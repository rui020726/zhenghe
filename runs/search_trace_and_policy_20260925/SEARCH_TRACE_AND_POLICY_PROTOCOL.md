## 一、对上一轮两份冻结文件的修订（R1–R5）

* **R1 — B1 是 S1 的硬前提，取消"缺日志仍可先跑"的口子。**
  旧协议 P0 允许"P0 不满足时只跑粗口径"。本轮**不采用**该分支：
  S1 矩阵只在 §四 的 B1 被动性验收与 §五 的正确性判定都通过后开跑；
  任一不过 ⇒ 停止在 B1，S1 结果件写 `not_run_p0_or_p2_not_met`，不产出任何"搜索侧效果"数字。
  理由：没有逐时刻证据的两臂差只能说明"未发现数变了"，不能说明它来自探测链还是来自覆盖，
  而本轮的目的正是把这两个解释分开。
* **R2 — 自变量只取 S1b。** 两臂固定为 A＝现有冻结 checkpoint 的 PILOC 策略、
  B＝现有 `FrontierSearchPolicy` 通过动作提供器接入**同一真实 PILOC 环境**。
  S1a（`search_agents` 2→3）**不选**；S1c 依旧协议默认排除。
  B 臂不得调用 mock 后端：mock 只在 `piloc_checkpoint is None` 时出现，本轮两臂都带 checkpoint。
* **R3 — 不使用 mock 后端替代真实环境。** `mock=False` 两臂逐字段相同并写入签名；
  任何 `MockGridSearchEnv` 读数都不进本轮任何结论。
* **R4 — 效应量单位统一并显式标注。**
  主口径单位＝**个/episode**（每集未发现目标数，分母 60 集）；
  批级口径单位＝**个/批**（每批 60 集合计）。换算 `1 个/批 = 1/60 ≈ 0.016667 个/episode`。
  旧协议停 1 的"上界 < 1 个/批"按原文单位**原样执行**，其等价数值为 0.016667 个/episode；
  两个单位不得在同一句里混用，每张表都带单位列。
  任务级读数（按时完成任务）单位＝**个/episode**，与目标级（未发现目标数）**不同分母、不相加**。
* **R5 — 原 S1 实质判据不因预期效果小而放宽；冲突时停在 B1。**
  停 1 / 停 2 / 守卫 G 的阈值、统计量、seed 数、bootstrap 设置全部按旧协议原文执行。
  若出现"同一份数据可被两个互斥解释唯一地各说一遍"的判据冲突
  （例：效果量过停 2 但机制记录里 `insufficient_logs` 或类别 1/2 非空，使因果指向不唯一），
  本轮**只交付 B1 与正确性判定**，S1 结果件写 `undecidable_criterion_conflict` 并停止，
  不自行挑选有利解释、不追加样本、不换统计量。

## 二、B1：真正记录探测时刻的快照

生产侧新增 `integrated_sar/search_probe.py`（默认关闭，`--search-probe` 给路径才生效），
并在 `piloc/src/Map/timemap.py` 增加一个默认关闭的开关 `search_trace_enabled`
（默认 `False`，与旧行为逐字节相同）。记录字段（每次 step 一条）：

| kind | 字段 | 来源 |
|---|---|---|
| `placed` | `goal_index, target_id, cell` | 适配器 reset 快照（第十七轮 F1/F2 的分母） |
| `step` | `step`、`actions`、`agents_before_move`、`agents_after_move`、`goals_at_detection`（探测时刻的目标格＋稳定 ID＋是否存活）、`observer_pairs`（目标 ID → 全部满足判据的观察者）、`env_deleted_target_ids`（环境自己判定发现并删除的 ID）、`adapter_event_target_ids`（适配器实际发出的 DetectionEvent 的 ID）、`remaining_after_move`（未发现目标移动后的新格）、`done`、`rewards` | 环境自己的判据原语 + 环境本步实际删除结果 + 适配器实际事件 |
| `final` | 终止原因（`all_found` / `step_cap`）、截止时搜索机器人格、截止时剩余目标格与 ID、逐步计数闭合 | episode 收尾一次 |

纪律（与 B0 同级，且更严）：

1. **快照取自探测时刻**，不用整步结束后的目标位置反推可见性：`goals_at_detection`
   是 step 开头、任何删除与移动之前的数组——它正是 `timemap.py:778` 的
   `_observed_goal_indices(self.agents_pos)` 与 legacy 分支逐 agent 循环所读取的同一数组。
2. **只读环境已有的计算**：`observer_pairs` 用的是环境自己的
   `_is_line_of_sight_blocked` / `_bresenham_line` 与它自己的 `self.map`，
   判据的持有者仍是环境；同时把环境**实际删除的 ID** 一起写下，
   使"由判据推出的集合"与"环境实际删除的集合"之间的任何分歧成为可见事实而不是猜测。
3. **不消耗随机数、不写任何状态**：探针不碰 `_py_rng`/`_np_rng`、不改 `goals_pos`、
   不进 actor 观测、不进奖励、不加 lifecycle `event_type`，只写侧文件。
4. **稳定 ID**：目标身份由 reset 顺序固定为 `piloc-e{episode}-target-{index}`。
   环境的 `goals_pos` 是只删不增的数组，删除会使**数组下标左移**，
   所以记录里同时写 `goal_index_at_reset`（稳定）与 `array_index_at_step`（会漂移）；
   任何分析都按稳定 ID 聚合，坐标只作为附注。
5. **多机器人看同一目标按目标 ID 去重**：`observer_pairs` 是"每目标全观察者"列表，
   事件数按目标 ID 计；**验收绝不要求"观察者—目标对数 == DetectionEvent 数"**，
   要求的是"有 ≥1 观察者的目标 ID 集合 == 适配器事件的目标 ID 集合 == 环境删除的目标 ID 集合"。

控制 seed 的选取规则（运行前登记，由 `sp_seeds.py` 从已交付归档确定性算出，
输入哈希写入账本）：在第十七轮 `UNDETECTED_GOAL_ATTRIBUTION.json` 的
`B1_d1_20260923` 批里，取该批 60 个 seed 中**未发现目标数 = 0** 的 seed，
按 seed **升序取前 4 个**。规则不看结果、不挑样本；清单一旦生成即冻结。

每条复现必须核对：历史配置逐字段、`map_sha256`、初始布局（机器人与目标）、
两个 checkpoint 的 SHA256、以及原有发现事件（目标 ID 与步序）。
**若旧配置无法恢复或轨迹无法复现**：记为"未复现历史运行"，
新运行只能说明当前行为、不得替代历史证据，不得把配置差异说成探测 bug，
不得删除不一致的 seed。

对每个遗漏目标输出实际时间线，并归入四类之一：

1. `probe_satisfied_no_env_deletion` — 探测时刻满足环境自己的真实判据，但环境未登记发现；
2. `env_deleted_but_event_missing_or_wrong` — 环境已发现/删除，但适配器漏发、错 ID 或重复发；
3. `never_visible_at_detection_step` — 实际探测时刻从未满足可见条件；
4. `still_undecidable` — 日志或历史复现不足，仍不能判断。

**类别 3 只表示"该次实现轨迹没有发生可见接触"**，不表示目标物理不可达，
也不表示其他策略必然能找到。

三条口径说明（写进每个结果件）：

* 初始位置可见 ≠ 第一次实际探测时仍可见（`Environment.step` 先移动机器人再判定）；
* 8 连通结论不能直接替代四方向机器人运动的可达性证明（8 连通是"可能被观测"的必要条件，
  不是"机器人走得过去"的充分证明）；
* 少量遗漏目标的距离中位数比较只是描述性证据，不能据此彻底排除放置因素。

## 六、阶段 R/S：只有正确性通过才开跑

* **判定门 P2**：类别 1、2 在 14 个 seed 全部为 0 且类别 4 为空 ⇒ `no_defect_found`，才允许进 S1。
* **若确认缺陷**：走修复分支——先加能稳定失败的回归测试；最小修复，优先让
  "事件"与"环境实际发现结果"共享同一来源；修复前后分别保留代码身份与产物；
  在受影响 seed 与控制 seed 上复测；更新报告、测试与文档后**推送并停止**。
  **本轮不同时开展搜索策略效果比较**（避免环境修复收益与策略收益混在一轮）。
  若进入修复分支，正式矩阵额度不转为无限调试预算。
* **frontier 输入核查（运行前先读代码，不临时改策略）**：`FrontierSearchPolicy` 只读
  `env.map`（障碍，用于四向合法性）、`env.agents_pos`、`env.global_pheromone`（**掩蔽到
  机器人自身视野窗**）、以及该机器人自己的时间戳观测；**不读 `env.goals_pos`**，
  不读未来状态。合法性用整张障碍图这一条与训练策略同源——
  `timemap.legal_action_mask(env, index)` 同样读 `env.map[nx,ny] != 1`，
  所以两臂的"合法动作知识"对称，不构成 B 臂额外信息。若发现越界信息 ⇒ 报告并停止正式矩阵。
* **登记在前的随机性声明**：同 seed、同初始场景**不保证**两臂后续目标轨迹或噪声实现逐位相同；
  策略改变发现/删除时机后会改变环境随机数消耗（目标每步的移动由 `env._py_rng` 驱动，
  少一个存活目标就少一次抽取；`update_timestamp_map` 每 agent 每步还抽一次视野噪声）。
  因此本轮只主张"**共享初始场景与 seed 的配对策略比较**"；
  除非另有逐步证据，不得写"完全相同的移动目标路径"；本轮不重构随机过程去强行制造这种一致。
* **一致性不变量（两臂都跑）**：环境实际删除的目标 ID 集合 == 适配器发出的 DetectionEvent
  目标 ID 集合 == 逐目标首次"有观察者"的步集合；逐步登记任何分歧。

正式矩阵：60 个新 seed `1200000..1200059` × 2 臂 = 120 episode。
使用前做全项目登记表 / 已录制流 / 日志 / 产物四源碰撞审计；
**若存在已使用记录，停止正式矩阵**，不顺延找"干净"编号；
不触碰 `800000..800399`（封存块盘上 artefact 须仍为 0），不与
`900000..900199`、`1100000..1100059` 重叠。冻结后不得根据中间结果调策略、换 seed、
改终止条件或追加样本。

主结果（旧协议原文，单位按 R4）：同 seed **未发现目标数差**（A − B），
配对百分位 bootstrap B = 10 000、RNG 固定并登记；同时报告逐 seed 改善/打平/退化计数。

预登记判据（原文照抄，不放宽）：

* **停 1（无对象）**：两臂未发现率都 < 0.5 %（60 集 × 6 目标 = 360 放置里 < 2 个），
  且差的 CI 含 0 且上界 < 1 个/批 ⇒ 该轴在此场景分布下无可测对象，关闭。
* **停 2（有对象）**：差的 CI 下界 > 0，且 ≥ 15/60 个 seed 贡献非零差 ⇒ 才可写成"搜索侧可动因素"。
* **守卫 G（机制不可判）**：某臂未发现目标里 `insufficient_logs`（本轮即类别 4）占比 > 20 %
  ⇒ 只报效果、不报机制，不得用几何距离代替位置路径。
* 区间内：如实报"未达判据"，正常交付，**不自动追加更强策略或训练**。

次结果（不参与判据）：发现数量与首次发现步分布、动态可见接触与发现事件的一致性、
系统按时完成任务数（用项目自己的 `window_metrics` 口径）、运行与推理成本。
**下游任务属性随发现位置/时刻生成** ⇒ 系统完成数差是搜索策略引起的**总系统效应**，
不得解释成"对完全相同任务集的分配能力提升"。
