# 多步发送诊断第一阶段：修订协议（启动前冻结）

日期：2026-09-22。分支 `analysis/comm-multistep-stage1`，起点 `docs/communication-multistep-start-plan@3cca880`。
对应总纲 v2.3 与 `COMM_MULTISTEP_STAGE1_NEXT_ROUND.md`。**本文件在任何真实 episode 之前写定。**

旧设计原件 `runs/comm_evidence_review_20260921/COMM_MULTISTEP_DIAGNOSTIC_PROTOCOL.md` 保留不改。
本文只登记**启动前的设计修正**，不是看新结果后改判据。

## 0. 本轮问题与边界

**问题**：单步 SEND/HOLD 的完成数相同，是否伴随后续补发？延长禁止重发窗口后是否出现更持久的差异？

这是 **ACK 规则**（`event_retry_until_acked_5`）下的局部机制诊断：

- 不是 ACK 模型训练，也不单独诊断既有 no-ACK PPO 模型失败原因；
- 不训练、不生成新流、不改生产默认值、不触碰 `800000..800399`；
- 不自动扩到 96 分支；总仿真启动（含失败）≤ **40**。

## 1. 相对旧设计的四条修正

| # | 旧设计 | 本阶段修正 | 理由 |
|---|---|---|---|
| 1 | 后续策略 `retry_until_acked(max_attempts=2)` | **`event_retry_until_acked_5`**（事件触发 + `max_attempts=5` + Event 默认 0.2/25.0） | 归档 `COMM_ACK_VALUE_COUNTERFACTUAL_25pct.json` 写明 `baseline_rule = event_retry_until_acked_5`；旧候选点来自该规则，换策略则时点无效 |
| 2 | 用 `actual_assignment` 与分配硬 mask 判 SEND/HOLD 合法性 | 只查**通信执行器**合法性：候选存在、内容/终态合法、剩余上行字节、订阅者计费、本步容量；与分配 mask 分开 | SEND/HOLD 是通信动作，不是分配动作 |
| 3 | 与已覆盖的旧点级 transcript 逐字复现 | 用本轮每点 **free 基线**核对干预前状态/轨迹；旧完整存档仅附加比较，缺失则标缺失 | 旧反事实 transcript 按 seed 命名会被同 seed 后续点覆盖，不能当逐字基准 |
| 4 | 先提交“尚未生成的分叉状态摘要”再跑 episode | 允许从 reset 确定性重放到通信决策钩子；顺序改为：冻结选点代码 → 初选清单 → free 基线与动作前摘要 → `POINTS.json` → 干预分支 | 不强求通用快照序列化框架；原顺序不可执行 |

## 2. 冻结配置（不得在新数据上重选）

完整机器可读配置见 `FROZEN_CONFIG.json`。摘要：

- 规则：`event_retry_until_acked`，`max_attempts=5`，`progress_threshold=0.2`，`urgency_time=25.0`，`policy_owned_timing`；
- 信道：隔离路径，上下行成功率 **0.7**（丢包率 0.3），延迟 0，ACK 反向同参数、counter-based RNG；
- 预算：任务上行 **29 300 B**；ACK 走独立反向账本；主成本 `total = uplink + ACK`；
- 流：仅 48 条训练流 `700000..700047` 的**已归档** `probe_points` 事前字段；
- 选流：`numpy.random.default_rng(20260921)` 对升序 48 seeds 不放回抽 16，**只用前 8**；
- 选点：独立 RNG `2026092101`，每流在 eligible 候选中选 1 点。

Eligibility（只读事前字段）：`0 < confirmed_fraction < 1` 且 `changed_view` 为真。
**禁止**读取分支得分、`send`/`hold`/`free` 结局或优劣标签。选择脚本自测不得依赖结局字段。

## 3. 规模与启动记账

| 项 | 上限 |
|---|---:|
| 选中流/点 | ≤ 8 |
| free 基线 | ≤ 8（每流最多 1 条） |
| 干预分支 | ≤ 8 点 × H∈{1,20} × 2（S/H）= 32 |
| **总仿真启动（含失败）** | **40** |

技术失败与从 reset 重放同样计数。不足规模如实报告，不补抽、不换 seed。

## 4. 干预定义

视图身份 `v = (target_id, revision, content_fingerprint)`。同一内容不得因尝试次数、ACK 状态或日志字段被误认新视图。

| 分支 | 定义 |
|---|---|
| `S(H)` | 在 `t*` **实际发射 `v` 一次**（经原广播/订阅者语义计费），其后在 `[t*, t*+H)` 禁止 `v` 重发 |
| `H(H)` | 在 `[t*, t*+H)` 禁止发送 `v` |

窗口语义：

1. 作用于**视图**，不作用于整个 target 或队列；其他 target / 消息 / ACK / 任务执行照常。
2. 窗口内出现**新 revision 或新 content_fingerprint** ⇒ 旧窗口**截断**（`window_truncated_by_revision`），记录截断步与有效窗口长度；新视图合法发送。
3. 窗口内该视图的重发在**实际通信发送入口**（`CommRelay._emit`）全部拦截，不能只拦策略请求路径。
4. **硬约束拒绝**（预算/容量/终态）与**窗口阻止**分开记账；窗口阻止的请求**不扣尝试字节、不消耗重试次数、不增加 sent_count**。
5. 强制 SEND 仍走 `_emit`：付不起则记 `refused_insufficient_credit`，**非法内容永不发射**。
6. 窗口结束后两分支交回同一条 `event_retry_until_acked_5`。

## 5. 执行顺序（取代旧设计的不可执行顺序）

1. 提交本协议、冻结配置、选择代码与源候选 JSON 摘要（本提交）。
2. 生成并提交**初选** seeds/时点清单（`POINTS_INITIAL.json`），此时 0 条新 episode。
3. 每流跑最多 1 条 free 基线：在指定 `t*` 验证候选身份与通信合法性，记录动作前摘要。
4. free 结束后提交验证过的 `POINTS.json` 与摘要。
5. 先跑第一个合法点的 4 分支（H=1/20 × S/H）并做机制检查；接口通过再跑其余点。
6. 接口失败：停止主运行；修复需新代码身份；保留失败产物。禁止边改运行源码边续跑。

选择规则在 free 结局出现前已冻结，**不能**用基线最终成败重新选点。

## 6. 动作前状态比较

比较时刻 = 目标动作生效前的**同一个通信子步骤**（`t*` 的 `_emit_selected` 之前），不是笼统的上一 tick。

状态覆盖：候选/队列、发送历史、策略计数、账本余额与已花、belief 指纹、在途事件与 ACK、模拟器时钟、相关 RNG 抽样计数。
RNG 抽样计数相同只是必要条件，不代替 RNG 状态一致。规范化摘要不得混入对象地址或无关路径。

free 与各分支从同 seed、同冻结配置 reset 后确定性重放到钩子处，比较摘要。
旧完整存档存在时附加比较；不存在标 `old_transcript_missing`，不因此编造复现通过。

## 7. 观察量（逐点成对报告）

- 最终完成任务、逐目标救回/新增失败；
- 上行 / ACK / total 成本；
- free 动作、同视图下一次发射延迟、新 revision 替代发射延迟（无则 `never`）；
- 首次 belief 分歧、补发前后是否重新一致；
- 请求被阻止次数、实际发射次数、窗口截断、重试计数、拒付、RNG 位移。

无后续发送记 `never`；任务结束或窗口截断不得误记为补发。

## 8. 机制验收（合成测试，不启动大批真实 episode）

启动前至少覆盖：H=1 边界；H=20 重试不漏拦；新 revision 截断；预算/容量不足；被拦请求不计发送成本；同 episode 多点文件不覆盖；reset 前缀可复现；正常路径卸载 hook 后不变。
临时 hook 用 `finally` 恢复。

**接口通过**需同时满足：干预前前缀一致、S 至多一次且合法、H 窗口无漏发、账本闭合、final 完整、无产物混用。

## 9. 判读边界（只用逐点描述）

- 不以 8 点 p 值或行级 bootstrap 作方法主张；不把多个 H/分支当独立样本。
- H=1 后短时补发且 belief/结果重新一致，H=20 持久分歧 ⇒ 支持“后续动作可能补偿单步影响”；**前向 RNG 位移等替代解释必须并列**，不得直接宣布 PPO 信用分配根因。
- 窗口很快被新 revision 截断、重试耗尽、无被拦请求 ⇒ 该点不能有效检验长窗口假设，不拿它证明时机无价值，不临时换点。
- 两 H 均打平 ⇒ 结论允许不确定，不关闭整个模型路线。
- 存在任务差异 ⇒ 仅证明该干预下可能有任务影响，不证明发送端观测可预测优劣，更不证明学习可赢。
- 本实验是 ACK 规则机制诊断，与此前 no-ACK 学习曲线分开解释。
