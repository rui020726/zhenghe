# ROUND28 协议：训练场景上的首报反事实样本诊断

执行依据 `EXECUTION_BASIS.md`（sha256 `f91858127f2f9ab6…`），起点 `5982677`。

## 性质

训练集机制诊断：把 ROUND27 的单案例发现扩展为一小批有明确来源的“发送端观测—首报动作—全局任务/成本变化”样本。不是独立验证集、不是训练、不是部署。

## 固定不变项

- 场景：1300000..1300015（原登记训练块 1300000..1300047 的前 16 个，`runs/comm_cost_v2_rerun_20260928/SCENE_REGISTRY.json` 登记）。
- 模型：seed 33 ep128，checkpoint `runs/comm_cost_v2_rerun_20260928/checkpoints/v2_train_s33_ep128.pt`，sha256 `52f490ab96a2ddad…`。
- 解码：原 greedy（SEND iff p(SEND) ≥ p(HOLD)，平手归 SEND）。
- 研究配置摘要 `dfc0e96a51c27fca…` 与 ROUND27 一致。
- 搜索、分配权重、环境、信道、预算、旁路、ACK、候选顺序全部不变。
- 不读接收端真值；目标 ID 只作记录和干预定位，不作新增特征。

## 启动预算

16 baseline + 1 禁用覆盖门禁 + 每场景每目标最多 1 条干预 = 正常上限 113；技术储备 7；硬上限 120。0 训练、0 optimizer.step、0 阈值调整。

## 干预点选择（冻结算法）

- 对 baseline 中每个目标：找它**首次真实合法可付**的首报决策机会（tape 中该目标第一次进入 actionable：顺序 shadow gate 判可付）。
- 只有该机会原 greedy 动作为 HOLD 才登记干预点。
- 排除原因分别登记：首个合法机会已 SEND / 无合法可付机会 / 从未发现 / 首发前终态。
- 选择器只读动作前候选、发送历史、有效顺序 mask、原 greedy 动作与时间身份；不读完成/过期/成本等结局；不许挑失败目标或“看起来最可能获益”的目标。
- baseline 产生后先冻结清单，再跑干预路径；不允许根据已见效果改算法。

## 门禁

- 首场景 baseline 与禁用覆盖路径行为逐字段一致、tape 逐行相同。
- 每条干预路径：干预步之前的 tape 与 baseline 逐字段相同；冻结点的状态（步号、特征、p(SEND)、报价、shadow 余额）必须在该场景 baseline 里逐字重现。
- 合成测试只做零环境、零 optimizer 检查；本轮不重跑完整生产套件（其范围已在 `ROUND27_SCOPE_REGISTRATION.json` 单列）。

## 判读纪律

- 每样本差值 = 干预路径 − baseline；保留正、零、负结果。
- 发射成功、消息被接受、改变分配、改变任务结局是四个不同标签。
- 最多 96 个干预只有 16 个场景：不当作 96 个独立场景，不把单目标收益相加预测联合发送。
- 新增发射改变后续随机数消耗：不宣称逐消息同批丢包；结果含闭环总效应。
- 不拟合阈值/分类器/新策略，不做显著性筛选，不凭小样本宣布特征足够或不足。
