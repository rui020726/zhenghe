## 4. 填写本表时必须遵守的禁则

1. **不得**把任何单元格之差说成因果结论（"因为通信所以任务多了 X"），除非该项来自本轮或后续
   轮真正做过的干预对照；描述性差值一律写"配对观测差"。
2. **必须**写分母：场景数、启动数、失败数、被剔除的行数（本轮行过滤口径是 ALL_ROWS 原编码，
   不启用 ACTIVE_ROWS，因此"剔除行数"应恒为 0，若非 0 立即报告）。
3. **不得**挑选 checkpoint：评估只认登记初值 ep0 与 ep128 不可变里程碑两个时间点；rolling 文件
   不是评估对象。
4. **不得**用开发块结果宣称"独立测试"；1.1 那块已被历轮使用。
5. 训练期的 loss / surrogate / g_hat / λ 轨迹属于**过程记录**，不得写成学习效果；本轮
   `LAMBDA_TRAJECTORY.json` 里的数字只能用于说明协议执行了。
6. 若评估跨进程读取旧 checkpoint，必须先过 `v2_trainer.load_checkpoint` 的版本门；旧轮
   （ROUND24/32）的 `.pt` 只能经 `load_checkpoint_read_only` 观察，其身份标记为
   `legacy_unversioned_capture_semantics`，不得与本轮 ep128 混在同一张表里比较而不标注。
7. 任何"跨 tick 无新动作行""首动作之前 prefix"两类情形的数字，若来自本场景块，必须写明该块
   内该类事件计数为 0（ROUND35 已证结构不可达），不能声称实机覆盖。
