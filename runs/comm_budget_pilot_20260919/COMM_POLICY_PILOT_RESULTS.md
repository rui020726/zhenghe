# 学习型发送控制 pilot 结果（COMM_POLICY_PILOT_RESULTS）

日期：2026-09-19　协议：`COMM_POLICY_PILOT_PROTOCOL.md`　清单：`COMM_ROUND_MANIFEST.json`
预算：`75pct = 87 900 B`（本轮自录训练流上无预算 `event` 均值 117 272 B 的 75%，见标定文档）
静默上界：非紧急 10 步 / 紧急 3 步，**写在传输层，规则臂与学习臂同一条**
验证集：`700048..700071`（24 条本轮新录检测流；`500000..500399` 未读未看）
单位：**按时完成＝该 seed 上在截止前完成的目标数**；**字节＝发送尝试的空口载荷（丢包照计）**；
**尝试＝发射×订阅机器人**；**应用＝真正改变了某台机器人 belief 的投递**；步＝全局时钟步。

## 一、smoke 六项全过（`PILOT_SMOKE.json`，`failures: []`）

| 检查 | 结果 |
| --- | --- |
| 预算从不超限 | always-send 臂花掉 85 710 / 87 900 B，执行器拒绝其余请求；`charge()` 越界会抛错（有单测） |
| 观测无泄漏 | 发送端可见字段全在 `SENDER_SIDE_FIELDS` 白名单内；越界即失败（单测 `test_comm_send_policy` 592 项的一部分） |
| 动作确实改变交付时刻 | always-send 与 hold-to-bound 的发射/尝试数不同（198 vs 89.8 尝试） |
| 参数确实更新 | 一次 PPO 更新后 trunk 权重最大变化 4.7e-3，16 个 minibatch，KL ≈ −1e-3 |
| return 与任务统计一致 | 逐 episode 断言"逐步奖励之和 == 生命周期日志的按时数"，不等即抛错 |
| 全等待策略不得得高分 | 关掉静默上界后：发射 0 次、被告知的 (机器人,任务) 对 0 个、按时完成 0 |

顺带暴露一件设计事实：**开着传输层上界时，没有任何臂能彻底沉默**——这正是 §4 要求的
"强制发送同样计费、也不能免费突破预算"的体现。

## 二、三个训练 seed 的学习曲线（贪心评估，8 个验证 seed，隔离无损）

| 训练步 | seed 1 按时 / 字节 | seed 2 按时 / 字节 | seed 3 按时 / 字节 |
| --- | --- | --- | --- |
| 40 000 | 3.50 / 86 742 | 3.50 / 86 742 | **6.00 / 59 915** |
| 60 000 | 3.63 / 86 747 | 3.50 / 86 742 | 5.50 / 49 646 |
| 80 000 | 4.38 / 86 781 | 4.13 / 86 475 | 5.50 / 47 359 |
| 100 000 | 5.25 / 86 514 | 3.50 / 86 593 | **6.00 / 34 882** |

100 000 环境步 = **只有 100 个 episode、25 次参数更新**（吞吐实测约 320 环境步/秒，单 seed 6 分钟）。
seed 3 一开始就找到了"该说才说"的策略，并继续把开销从 59.9k 压到 34.9k；
seed 1 在缓慢爬升（3.5 → 5.25）尚未收敛；seed 2 停在"到处乱发、额度耗尽"的状态。
**这不是收敛结论，是方差结论**：同一算法、同一预算，3 个 seed 里 1 个找到、2 个没找到。

## 四、§8：把现场感知与 gossip 换回来（部署设置，同额度，24 seed）

| 臂 | 按时完成 | 空口字节 | 发送尝试 | 应用投递 |
| --- | --- | --- | --- | --- |
| 无预算参照 | 5.958 | 116 753 | 262.8 | 262.2 |
| `periodic_5` | 5.958 | 70 542 | 159.0 | 117.2 |
| **learned seed 3** | **5.958** | **29 009** | 64.8 | 46.2 |
| learned seed 1 | 5.833 | 86 026 | 198.2 | 181.8 |
| `event` | 5.792 | 86 433 | 196.5 | 196.2 |

配对差：learned 3 − `periodic_5` 按时完成 **0.0 [0.0, 0.0]（24/24 逐 seed 相同）**，
空口字节 **−41 533 [−45 780, −36 989]**（省 59%）；相对 `event` 规则则省
**57 424 B [−62 877, −51 120]**。

结论与上一轮的旁路测量一致：**部署设置下完成率被现场感知顶住（各臂打平，无从提升），
可部署的收益是"同样的完成率、显著更少的受控通道开销"**；
learned 3 在此发送的 64.8 次尝试中只有 46.2 次真正改变 belief——
其余被视距/gossip 抢先，这正是"受控通道成本"与"全系统信息到达"必须分开报的地方：
本表只计前者，后者的免费份额已由上一轮 95.6% 首次知晓替代率与 177 335 次视距写入量化。

## 五、规则臂之间也要报告的两件事

1. `immediate`（只发首次检测）在**三个档位上从不触顶**（自己只用 14 737 B，0 次被拒），
   因此预算对它是惰性的，而它反而胜过同一额度下的 `event` 与 `periodic_5`
   （75% 档 5.583 vs 5.250 / 5.438；50% 档 5.583 vs 4.396 / 4.938；25% 档 5.583 vs 3.521 / 4.000）。
   ⇒ 单看"按时完成"，便宜规则在有预算时并不弱；学习臂要打败的是"最省规则"，不只是"最准规则"。
2. `event_priority` 与 `event` 在两个设置上几乎逐位相同（差 ≤34 B），
   因为每步通常只有 1–2 个候选，排序权在少数拥堵步才起作用；
   它在丢包诊断上略好（+0.042，CI [0.0, +0.125]）。

## 六、判定（按协议 §9 的分支）

- **不成立**："学习策略在同预算下稳定优于最强规则"。三个训练 seed 只有 1 个做到，
  且对最强规则 `periodic_5` 的完成率差不显著（CI 含 0）。
- **成立**："在预先规定的完成率容忍范围内降低通信"：seed 3 在三个设置上一致地
  以 41–59% 的空口开销换来与最强规则**不劣于**（无损、部署）或**更好**（有损）的按时完成，
  字节差的 CI 全部显著。这正是本轮预设的可行胜利口径。
- **诊断（规则明显占优的那一支怎么读）**：seed 2 显著更差，seed 1 尚未追上——
  100 个 episode / 25 次更新的先导预算**不足以判定"没有学习空间"**。
  三条证据支持"训练不足"而非"观测不足"：
  (a) seed 3 用同一观测/同一算法立刻达到天花板，说明信息够用；
  (b) seed 1 从 3.50 单调爬到 5.25，仍在上升段；
  (c) 失败模式是"到处乱发到额度耗尽"（被拒发射 1380 次、尝试数与规则臂同级），
      是探索/步数问题而非观测缺特征问题。
- **下一步最有依据的一项改进（不扩动作空间）**：把每更新的 episode 数与总步数按吞吐提升
  （4 → 16 episode/更新、100k → 400k 环境步，≈2×25 分钟/seed，3 并行仍 <1 小时），
  并把 λ/熵退火与"预算接近耗尽时提高强制发送权重"作为**预先登记的**训练细节；
  动作空间仍固定为 send/hold，收件人选择与路由继续不学。判定线：
  若扩大训练后 3/3 seed 对 `periodic_5` 的字节差 CI 上界 < 0 且完成率差 CI 下界 ≥ −0.05，
  才值得预注册新的独立测试（`500000..500399` 或再录新块）去做正式验收。
