# 掩码原因诊断：谁替策略做了决定，以及这句话的分母是什么

日期：2026-09-20。分支 `feat/comm-policy-owned-timing`，对应总纲 v1.5 §5.7 与
`COMM_PROTOCOL_V2_NEXT_ROUND.md` §2。机器可读：`COMM_MASK_CAUSE_AUDIT.json`。

本轮训练开始**之前**的小诊断。它要回答的不是"学习值不值得做"，而是一个更前面的问题：
上一轮报的两个数字能不能合成一句话。

## 〇、为什么先做这件事

上一轮 `COMM_TIGHT_BUDGET_RESULTS.md` §三 写着：

> **25% seed 1/2 卡在额度上**：全程 96–97% 额度、auton≈1.00、可选候选只占 3.7%–9.1%，
> ……紧额度下**大部分话是上界替它们说的**，学习能撬动的余量本来就小。

同一份 §五 局限又写"学习臂可选候选仅占 3.7–9.1 %"。这两个百分比是**候选格**占比，
而"auton≈1.00"是**字节**占比（自主发送字节 ÷ 全部发射字节）。前者分母是"这一步这条目标被摆上桌"的次数，
后者分母是"实际上过空气的包"。一个被掩掉的候选永远不会变成第二个分母里的一项，
所以**这两个数不能互相解释**。诊断要做的是把它们分开称：被掩掉的候选里，究竟有多少真的变成了上界替它发的包。

## 一、口径与优先级（先写定，再计数）

设置：隔离无损（`gossip_interval=100000`）、丢包 0、`legacy_shared_bound`（旧协议，本轮主诊断对象）、
每臂每档 8 条**训练**流（`700000..700007`，绝不使用验证流）、额度 29 300 B 与 87 900 B。
臂：5 条固定旧规则 + 上一轮三条学习策略的 **400k 末轮 checkpoint**（从盘上重读，不重训；
权重指纹随 `rule_matrix`/manifest 记录）。

分类器坐在发送策略的接缝上，只读不写：先让被包裹的策略自己决定，再对**这一步被摆出的每个候选**记
多标签原因，并按固定优先级取一个互斥主原因（优先级在看数之前写在这里）：

| 主原因 | 判据 | 含义 |
|---|---|---|
| `bound_send` | `age_steps ≥ (紧急 3 / 否则 10)` | 上界已经接管这条变化，无论策略怎么答它都会（试图）出去 |
| `capacity_full` | 本步发射槽已用尽 | 现在开口必被拒（本配置的 `sends_per_step` 未设，故恒为 0） |
| `credit_unaffordable` | 传输层自己的成本函数 + `budget.can_send` 在**步初余额**下判假 | 现在开口付不起 |
| `content_redundant` | `changed_view` 为假 | 可以说，但说了等于没说（与上一封内容逐字段相同） |
| `free` | 以上皆非 | 真正的 SEND/HOLD 抉择 |

三条纪律：**没有候选的 tick 单列**（`ticks_without_candidates`），不进自由候选分母；
**上界已到但付不起 → 记为拒付**（`refused_forced_maxwait`），绝不记成"强制发射"；
**优先级会掩盖共存**——一个格可以同时是 `bound_send` 与 `credit_unaffordable`，主原因列只显示前者，
所以正文一律同时给多标签列，并把"实际发射数"当作裁判。

可复现性校验（全部实测通过，见 §四）：成本预测对每一个实际发射逐格等于转录里的 `cost_bytes`；
分类器判定的接管集合覆盖转录中全部 `forced_maxwait` 发射；同一格去掉记录器重跑，字节/发射/完成数/
配置哈希全同。

## 三、这份表说什么，不说什么

**说的（对上一轮那句话的判定）**：紧额度下"大部分话是上界替它们说的"**不成立**。
25 % 档上 learned1/learned2 的上界代发发射数是 **0 次、0 B**，自主字节份额 1.00 就是字面意思——
它们发出去的每一个包都是自己请求的；上界在它们身上想说的 8 655 / 17 165 次全部**落入拒付路径**。
真正被上界代发的是 `hold_to_bound`（100 %）、`immediate`（52 %）和 learned3（26 %）。
`periodic_5`、`event`、`event_priority` 同样是 0 %。

**说的（那 3.7–9.1 % 是什么）**：它是候选格里"仍归策略选"的比例，本诊断在同一批臂上重算为
**0.7 %–4.5 %**（数量级一致，绝对值不同：本诊断用贪心评估与 8 条训练流，上一轮那列来自随机采样的
训练 rollout 全程均值）。它的**成因是额度**，不是上界：把每格的标签与"本集首次拒付步"前后切开，
`learned2@25%` 首封拒付之前 free 格 114 / 172，之后 free 只剩 7 而 `bound_send` 冲到 17 165。
`immediate@25%` 同理（之前 622，之后 3）。也就是说：**先把额度花光，候选才批量变成"上界已到且付不起"**。

**说的（75 % 档的机制正好相反）**：该档对四条臂（`immediate`、`hold_to_bound`、learned2、learned3）**零拒付**，
额度不 binding，上界确实是主要代笔者（`immediate` 58 %、`hold_to_bound` 100 % 代发），
这与第三轮"75 % 档只用掉 0.40–0.45 额度"的结论一致。

**不说的**：本诊断**不能**用来支持"取消上界学习就会赢"，也不能用来支持"额度才是唯一瓶颈"。
它只固定三件事：两个百分比的分母各是什么；上界在哪些臂上真的产生了包（且这些包是计费、可拒付的）；
紧额度下策略失去选择权的直接原因是额度耗尽。协议实验值得做，依据是"旧协议存在代发/拒付这条混淆"，
而不是"上界是唯一瓶颈"——这一点与 §1 的写法一致：**依据支持做实验，不证明必胜**。

**一个值得单独登记的观察**：`learned2@75%` 与 `hold_to_bound@75%` 在本诊断里**逐列相同**
（候选格 1 939、free 70.24 %、发射 117、代发 117、字节 309 600、完成数 5.875），
是继第三轮（400k 逐值相同）、第四轮（24 条验证流逐值相同）之后**第三次**在完全不同的输入上复现；
`event@75%` 与 `event_priority@75%` 也逐列相同（优先级只在拒付时才有意义，该档这两臂零 forced 拒付）。

## 四、校验与产物完整性

| 检查 | 结果 |
|---|---|
| 记录器非侵入（同一格去掉记录器重跑，比字节/发射/代发数/完成数/生成数/配置哈希） | 128/128 全同 |
| 成本预测 vs 转录实收字节（对每个实际发射） | 比较 1 674 次，**不一致 0** |
| 分类器接管集合 ⊇ 转录 `forced_maxwait` 发射 | 漏计 **0**（128 集合计 521 次代发全部命中） |
| 成本/投递/发送原因恒等式残差 | 全 0 |
| 每集 `Σ 主原因格数 == 候选总数` | 128/128 通过（合计 110 297 个候选格，不等即抛错） |
| 归档逐格复现：本轮 25 % 档重跑 vs 第四轮 `probe_after` 转录 | **40/40** 发射数与字节逐格相同 ⇒ 旧模式在本树未变 |
| 第四轮 `probe_after` 转录能否复核 75 % 档 | **不能**：文件名只含臂与流，两档互相覆盖（见下） |
| 本轮自己的产物命名 | 一律带档前缀（`cell_<tier>_…`、`row_<tier>_…`、`evaluation/<tier>/`），并显式拒绝对同一目录跨档复用 |

**登记的归档缺陷（上一轮产物，原样保留不删改）**：`runs/comm_tight_budget_20260919/probe_after/`
里 `ct_<arm>_s<seed>.jsonl` 与 `rp_/tr_` 同族文件**不带预算档标识**，两个档共用同一目录 ⇒ 后跑的档
覆盖先跑的档。该轮**发表的** `COMM_TIGHT_BUDGET_GATE.json` 是按档聚合的（在内存里算完再写），
其数字不受影响；受影响的是"事后从转录复核 75 % 档"这条路径。第四轮已经在本轮的
`evaluation/` 上修过同族问题（`evaluation_root(tier)`），但没有回溯 `probe_after/`。
本诊断用文件内 `max(spent_after_bytes)` 反推每份转录属于哪一档，只接受同档比对，
不同档的 40 格记为 `cells_not_usable` 并逐条给出理由，不当作不一致，也不假装复现过。

## 五、上一轮文档的两处文字问题（勘误，原文保留）

| 位置 | 原文 | 核定 |
|---|---|---|
| `COMM_TIGHT_BUDGET_RESULTS.md` §〇 表末行 | "3 164–6 068 次 optimizer.step，18.8 万–37.7 万条决策样本" | **正确**。`COMM_TIGHT_BUDGET_MANIFEST.json → training.runs[*].decision_samples` = 351 539 / 376 611 / 353 283（25 % 档 seed1/2/3）与 298 410 / 188 384 / 239 803（75 % 档），区间 188 384–376 611 |
| 同文件 §五 局限第三条 | "训练量按决策样本看仍偏小（**1.9 万–3.8 万条**）" | **十倍小数错**，应为 **18.8 万–37.7 万条**（188 384–376 611）。同一句里"optimizer 步数 3.2k–6.1k"（§五 不成立段）与 manifest 一致，故错的是样本数一侧。定性说法"仍偏小"本身保留：188 k 条决策样本 ÷ 6 运行 ≈ 每次 3.1 万–6.1 万条，仍是小样本 |

另两处**推论强度**更正（§2 明确要求，属于"由有限证据推出过强结论"）：

1. §二 末"学得动，但**学到的极限就是规则**"→ 应为"**本轮训练得到的策略收敛到了规则，未越过预注册门槛**"。
   3.2k–6.1k 次 optimizer.step 与 188 k 条决策样本不足以刻画"极限"；平台也不刻画优化充分性。
2. §五 成立主张 2"即当前观测/动作空间下'该说的规则会说、学习臂也会说'，**学习没有额外信息可用**"→
   应为"**本轮这些策略在逐流完成数上与规则相同**"。逐流完成数相同不等于动作序列相同，
   更不等于该观测/动作定义下不存在携带额外信息的策略；这正是 §6 要求"检查动作/消息序列，
   不能只凭完成数逐流相同就声称策略逐位相同"的同一件事，本轮已把它写成协议条款。
3. 同时补一句限定：**选点后的初值增益不是训练充分性的证明**。上一轮六个运行都优于各自初值，
   只说明修正采样器后学习过程可复现地改善，不说明它已到达该配置的上界。

## 六、这一节是否发现"影响本轮有效性的真实正确性缺陷"

**没有。** 三项会阻塞协议的检查全部通过：代发确实计费且可拒付、拒付不被记成发射、
旧协议在本树逐格复现归档；成本恒等式残差为 0。发现的两个问题（十倍小数、75 % 档转录被覆盖）
是**记录与归档**问题，不改变任何一条结论的方向，按 §2 的指示只出勘误与登记，不扩成全系统审计。
因此按指令进入协议实验。
