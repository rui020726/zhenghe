# 步骤③：显式优化通信成本、同时约束任务效果的最小学习控制器（设计，未实现）

本轮 0 训练、0 生产代码改动。本文只交付一份**可批准的设计**：它规定目标函数怎么写、
约束落在哪、复用哪些既有件、禁止碰什么、判据用什么口径，以及一个必须诚实写在前面的预期——
**这条路线的合格出口有两个，其中不需要学习的那一个同样是结论**。

数字来源：`COMM_COST_COVERAGE.json`、`LEARNABILITY_PROBE_OFFLINE.json`、
`ROUND18_ARCHIVE_CLOSURE.json`（本轮实测，0 新 episode）；纪律来源：`AGENTS.md`、
`PROJECT_CHARTER.md` §6.3/§7/§8/§10/§11、`runs/comm_research_closure_20260923/`。

## 一、把研究问题写成一道约束题（全文唯一的形式化处）

在**部署信息路径**（`gossip_interval=2`、`comm_range=0.3` 保持生产值，不关旁路）上，
对控制器 π 求：

```text
最小化   E[airtime_bytes(π)]                      ← 显式的成本目标
约束     E[按时任务(π)] ≥ 同预算规则基线 − δ        ← 任务效果只作约束，不作目标
         E[expired(π)]   ≤ 同预算规则基线 + δ′
         硬额度与每拍容量由执行器执行，任何一臂都不得绕过（§6.3）
```

报告形式是**实测 Pareto 台阶**（"守住效果的最低额度档是多少字节"），不是任何加权和：
第十五轮已经证明，把成本与效果压成一个标量系数，在前沿退化为 1 点时**无从选系数**
（`COMMUNICATION_RESEARCH_CLOSURE.md` N4、总纲 §6.3:1189、:1592）。

## 二、成本进目标函数，但不进 reward —— 这是本轮要解的那个结构问题

现状是结构性的：**字节从来不是目标**。`reward` 只奖励按时完成
（`PROJECT_CHARTER.md:425`："当前 reward 只奖励按时完成，字节是硬约束与事后指标"），
成本只以硬额度（`comm_budget.py:3-16`）和事后计数（`comm.py:974`）存在。
所以"省通信"不会被自动学出来——这不是调参能解决的，缺的是**目标的一侧**。

两种写法，本轮只推荐第一种：

| 写法 | 机制 | 本轮判定 |
|---|---|---|
| **(A) 字典序 / ε-约束额度扫描**（推荐） | 成本由**额度档 B** 承担：B 逐档收紧；同一 B 下只比效果；报"效果守得住的最小 B"。目标函数写在**实验设计**里，不写在 reward 里 | 0 新机制：硬额度、逐尝试计费、三本互斥账（policy/forced_maxwait/other，`comm.py:363-371`）全部已实现；不需要任何新系数；天然满足 §6.3"所有策略共享同一硬预算执行器" |
| (B) 成本系数 λ / Lagrangian | reward 里出现 −λ·字节，或对约束做对偶上升 | **本轮不推荐**：λ 需要一条非退化的成本—效果前沿才能标定，而部署路径上前沿只有两端点（0 B 与 14 573.3 B）。这正是 N4 禁止的动作（"不得用未通过门槛的层去挑成本系数"）。**作为下一台阶保留**，前置条件是 pilot 至少产出 3 个 binding 的部署内点 |

**关键区分（防自欺）**：在 (A) 里，"省"必须是**策略选择不发**，不能是**执行器拒付**。
两者计费口径不同（被拒的发送不计费，`comm.py:899-923`），所以主指标只取
policy 归因的 attempts 字节，`budget_refused_sends` 与 `capacity_refused_sends` 单列并报；
一臂若把额度打满，那是额度在决定流量，不能写成它的功劳。第十五轮同一教训的反面表述：
"靠丢掉流量来省不是省"（丢包照付）。

## 四、公平基线必须由步骤②的读数重写成三条臂

`COMM_COST_COVERAGE.md` §三把"强规则"拆成了三件不同的事。落到这台控制器上，
pilot 必须同跑（同 seed、同额度、同协议功能）：

1. `always_hold` —— 0 B 地板：没有它就无法说明"省下的字节买到了什么"；
2. `immediate` —— 现状默认（14 573.3 B/ep）：没有它就无法说明"降本"是否只是不发；
3. **`late_only` 规则臂（需要一次最小生产实现，待批准）** —— 只在 `step > k` 时报首报，
   `k` 在**开发/验证 seed 段**上选定（§8.1:1227 允许规则参数在同一范围内公平选择）。
   这是学习器**唯一必须击败的东西**，也是把 §二(A) 的额度档填出内点的便宜办法。

`send_once` 在部署路径上与 `immediate` 行为重合（那里本就没有刷新），
所以它**不是**这条路径的降本基线——不得沿用第十五/十二轮隔离表里的"最强规则"称号
（`comm_policy.py:305-307` 那句 `event_priority` 自述"最强简单规则"也与实测前沿矛盾，
本轮按实测取值，不改该 docstring，登记于此）。

## 五、这条路线可能不需要学习：把这句话写进设计，而不是藏在结果里

探针的读数（`LEARNABILITY_PROBE_OFFLINE.json`，反事实记账，非实测）：
在部署默认难度上，`step > 147` 一个阈值 ≈ 21.9 % 的账单（3 212.2 B/ep）
即可保住归档里全部 352 个按时任务，承重召回 19/19；而 19 个承重的**剩余时间反而更多**
（中位 136.8 对 115.8 秒）⇒ 决定性的量是"发现发生得晚不晚"，不是"任务紧不紧"。
同时，部署路径上 352/352 都是首报、`revision` 恒 1、`members` 恒空 ⇒
19 维里 8 个变化检测维度是常量。

因此本设计的合格出口写成两个，**预先固定、不看完结果再挑**：

- **出口 P（正向）**：学习臂在**同额度**下 Pareto 支配 `late_only`（更字节少且不更差，或
  效果更高且不更字节多），CI 支持 ⇒ 首次建立"学习相对强规则的附加价值"。
- **出口 N（负向且同样合格）**：`late_only` 已吃满该额度档可达的前沿，学习臂不构成支配 ⇒
  与第十五轮收束一致，**在该操作点上**再次确认学习无附加价值，且这次给出的是
  **成本目标显式化之后**的读数。

出口 N 不是失败，但**不得**被写成"学习普遍无效"；反之出口 P 也**不得**被写成
"降本已解决"，因为阈值是代理变量（§六）。

## 六、这个设计不能承诺什么（缺口都在明处）

1. **78 % 降本不是结论**：切点读自同一批 60 seed，未过未见 seed；混合静默下的运行不等于任何
   归档臂（免费视距信道取决于机器人位置，位置取决于被告知了什么）。
2. **机制未被指认**：真正决定冗余的是"有没有够能力的机器人会在截止期前走进视距"，
   它需要机器人位置，而发送端被禁止使用 ⇒ 现有可见特征只能提供代理。若 pilot 想学机制，
   那是一次**观测契约变更**（新授权），不是训练量能补的。
3. **两条免费信道无法分别归因**：视距刷新与一跳 gossip 同函数同开关
   （`old_task_env.py:477-512`、`:1107-1110`）⇒ 不能说"省的是 gossip 的钱"。
4. **部署 + 真预算的格子一个都没有**：磁盘上部署配置只有 0 B 与 14 573.3 B 两端点；
   内点只能实测，这正是 pilot 存在的理由。
5. **冻结的 6 目标部署难度没有按时失败可约束**：A1 352/352 全按时；第十八轮 120 集里
   "发现但未按时"合计 2 个 ⇒ 判据分母为空（第十六轮 `undecidable` 的同一件事）。
   ⇒ pilot 必须先做一次**运行点标定**，且标定规则与任何臂的胜负无关
   （§11:1457 明确禁止"用更紧 deadline 让学习显得有优势"；见 pilot 件 §二）。

## 七、对学习型通信控制主线意味着什么 / 不意味着什么

**意味着**：主线回到"何时传递任务信息"这一原题，并且第一次把成本写成**被优化的对象**
而不是事后计数；这一步不需要新数据、不需要训练、不改生产默认值，只需要上述目标函数与
一条规则臂的实现授权。**不意味着**：通信降本已经被证明可学；不意味着部署路径上的
冗余是学习独有能发现的（现有证据相反，见 §五）；不意味着搜索侧结论需要修改
（第十八轮按 `ROUND18_ARCHIVE_CLOSURE.md` 原样归档）；不意味着可以引用隔离路径的
`send_once` 前沿作为部署降本依据。
